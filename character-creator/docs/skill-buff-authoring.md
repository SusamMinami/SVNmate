# 技能与 Buff 模块契约

状态：本地源码已实现。表侧写入遵循原有整批预检、串行 COM、标红和未保存协议；
不自动保存、导表或写 UE。UE 侧边界见 [接口复用](ue-interface-reuse.md)。

## 模块与新建

| 配置 | 支持的模块 | 模板新建行为 |
| --- | --- | --- |
| Skill | 身份/职业、Ability、冷却/充能、组合/结束、PVP/矿战 | 复制技能、所有直接关联技能树、全部 `id // 1000` 对应升级行 |
| Skillsystem | 解锁/前置、位置/上限、描述/标签、PVP | 随技能新建；各树 ID 由用户明确指定 |
| Skillupgrade | 技能点/需求等级/战力、PVE/PVP 成长描述和跨列参数 | 新 ID 为 `Skill.id × 1000 + 原等级` |
| Buffbase + Buff | 身份/显示、叠加/生命周期、属性/表现、行为/光环/后继、技能替换/CD | 复制一条完整模板行；按需编辑并关联新效果 |
| Skilldamage | 伤害类型/公式、属性数组、三个 Buff 槽位、能量 | 复制一条模板行；重复子成员位置完整保留 |
| Behavior | 触发时机/条件/概率/CD/对象、Buff/伤害/技能/衍生行为 | 复制一条模板行 |
| Aura | 范围/挂点/阵营、Buff 槽位和重上间隔 | 复制一条模板行 |

不自动为所有 Buff 复制行为/光环/互斥等附表。用户在同一职业上下文按需新建记录、
填写明确的引用，统一加入审核。面板不执行公式，字符串 DSL 原样作为文字写入。
当前只能复制已有等级行，不自动插值或生成超出模板的升级曲线。
未适配的被动、特殊类型参数、融合、互斥、表现资源字典由原工具维护。

## 身份与引用

基础职业与转职 ID 始终独立。CreateRole 的 careerid 用于标识创角基础职业，
IsIntroChar 用于标识新手本，既有 BP 路径只用于显示角色族，不用于合并记录。
修改已有 Skill/Buff 可能影响其他职业，复制技能不会修改模板所属职业。

后端只接受 `authoring_schema.py` 的完整成员白名单。
Buff 主表同时拥有 `Buffbase.*`、`Buff.*`，不能给所有字段强加同一前缀。
数组起点及终点显式声明，内部空槽和重复成员不转为字典。

已核对的重要语法：

- Skillsystem.skillid / partnerskillid 指向 Skill；chiefskill / Replaceskillid 指向
  Skillsystem。后者已核对 `UI/Skill/SkillManager.lua` 对 `SeriaCfg.Skillsystem` 的读取。
- Buff.behavior 指向 Behavior，auraid 指向 Aura，多个 ID 用分号分隔。
- Buff.nextbuff 为 `ID` 或 `ID,层数`，多组用分号分隔；不是单一裸整数。
- Buff.changeskill 为 `旧SkillID;新SkillID`，多组用逗号分隔。
- Behavior.behaviorskillid 为 `SkillID:等级`，多组用分号分隔。
- Skilldamage.skillbuff 是三个固定四元组：buffid、命中、效果、持续时间。
- Aura.buffinfo 槽位为 `BuffID;参数`。

引用按各自目标表检查存在性；同一批新建记录也参与引用解析。
Skill 与 Buff 同号不构成关联。伤害记录必须通过明确 ID 打开，
面板没有把同号伤害自动挂到某个技能。

校验不会重新解释未修改的旧引用/DSL；新建复制也保留未修改的外部依赖。
因此模板可能带有历史无效内容，新建草稿不是完整依赖闭包认证。
新 ID 唯一性、数组宽度/边界、修改字段类型/枚举、已适配引用由服务端校验；
对未适配命名空间、公式语义和 UE 资产只说明边界，不作通过声明。

## 批次与 Excel

每批最多 200 条效果配置记录；新技能必须带齐模板的全部树/升级行，
后端复核树指向与等级 ID。职业基础修改可以与效果配置同批提交。
升级 ID 遵循生成表定义的 32 位整数范围，伤害 ID 使用 64 位整数范围。

准备时按工作簿缓存只读解析，逐行定位源 ID、表头、原值、版本及文件指纹。
仅在全部差异形成后发出服务端单次审核凭证，客户端不能提交任意文件/单元格坐标。
同名工作簿来源不唯一、源 ID 多版本/重复、Excel 原值与已编辑字段的 CSV 不一致时拒绝。

COM 整批预检后，每个源工作簿只生成一个副本，每个新记录分配独立追加行。
先复制所有模板行，再执行字段编辑，避免同批对模板的修改污染后续复制。
完整源行复制保留公式与格式；新增 ID 和审核修改标红，结果保持未保存。
失败尽力恢复本批修改；不承诺跨工作簿原子事务。

## 前端草稿

技能、Buff 与基础配置共享当前职业的草稿/回执，按目录及全部已加载表快照隔离。
切换记录或职业不丢草稿；刷新恢复 sessionStorage，容量不足时仍可继续本页编辑。
新建默认采用已显示模板的编辑意图，再应用后端的明确 ID/职业重映射。
所有实际写入集中在“检查写入差异”与对应审核弹窗。

## 验证入口

`tests/test_authoring.py` 使用合成 CSV/xlsx 验证复制完整性、不同命名空间、
新引用、数组定位、ID 冲突、快照和只读审核。
`tests/authoring_excel_smoke.py --run` 才执行合成工作簿 COM 写入。
`tests/authoring-ui.mjs` 使用真实快照做读取/审核，但拦截 commit 返回合成回执。
