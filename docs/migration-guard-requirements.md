# 海外迁移核验助手：需求说明

## 1. 文档状态

- 产品名：迁移核验助手（`MigrationGuard.exe`）
- 运行平台：Windows 桌面端
- 当前实现版本：`1.0.5`
- 最近核对：2026-09-11
- 当前流程：开发主干 `trunk` -> 海外 `trunk` -> `OSOB`，以及国内
  `trunk` -> 国内 `OB`
- 产品与视觉入口：`migration_guard/PRODUCT.md`、`migration_guard/DESIGN.md`

本文是现行行为需求。技术实现与未落地设计见
[`migration-guard-design.md`](migration-guard-design.md)；面向用户的操作步骤见
[`../README_migration_guard.md`](../README_migration_guard.md)。

## 2. 问题定义

组内日常迁移同时跨越 Jira、SVN、Unreal Editor 和人工提交窗口。现有工具可以按
Jira 单号找到资源并发起迁移，但无法稳定回答下面三个问题：

1. 源单实际涉及哪些文件和提交？
2. 每个源文件在目标工作副本中是否已经产生对应变更？
3. 这些变更是否已经使用正确的海外单号提交到目标 SVN？

因此，“工作副本干净”不能直接视为迁移完成。它也可能表示文件从未迁移；同样，
“已打开 TortoiseSVN 提交窗口”也不能证明提交已经成功。

## 3. 产品目标

工具需要为每个迁移单建立一份可重复核验的迁移清单，并把结论归纳为：

- **未迁移**：源文件存在，但目标没有本地变更，也没有目标提交证据。
- **待提交**：目标已经产生本地修改、新增、删除或替换，但尚未提交。
- **已完成**：目标存在对应单号的提交记录，且目标工作副本没有该文件的遗留改动。
- **需确认**：检测到同路径的其他提交、无需迁移、路径改名、外部目录等无法自动判定的情况。
- **阻断**：工作副本冲突、路径映射失败、SVN 命令失败或源清单不可信。

当前非空任务中的文件全部为“已完成”“已提交”或有删除证据的“源已删除”才聚合
完成。“人工批准无需迁移”的持久记录仍为计划，不是当前可用的完成捷径。

## 4. 非目标

MVP 不做以下事情：

- 不自动点击确认并提交 SVN。
- 不自动解决 SVN 冲突。
- 不替换 `SeriaMigrateInfo` 的资源迁移实现；桌面工具只负责批量编排调用。
- 不承诺比较两个 `.uasset` 的语义是否完全一致。
- 不根据“文件存在”或“目标目录是干净的”推断迁移成功。
- 只读核验不改资源；显式 UE 迁移仅处理已确认目标，不擅自修改源资源或额外目标。

## 5. 使用角色

主要用户是负责把开发主干内容迁移到海外分支的策划、程序或资源维护人员。用户需要
在一次操作中处理 `res`、`doc`、`bin` 中的一个或多个模块，并可能同时面对
SVN externals、多个源提交、多人提交和同一文件的后续修改。

## 6. 核心输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 待识别 Jira 单号 | 是 | 可输入 `SERIA-12345` 或 `OSCOA-67890` |
| 目标 Jira 单号 | 按路线确定 | 海外用 OSCOA；国内 OB 使用与源相同的 SERIA |
| 飞书固定表 | 海外映射时需要 | 分别配置 Trunk/海外 OB 工作簿，国内 OB 不依赖 |
| Jira 只读状态 | 自动 | 读取国内/海外工单状态、创建时间和版本登记；不要求本地工程 |
| 工作区配置 | 精确核验时必填 | 国内 trunk、海外 trunk、海外 OB，以及可选的国内 OB 工作副本 |
| 查询起点 | 自动，可调整 | 优先读取 Jira 创建时间；失败时使用用户设置的日期或版本号 |
| 作者 | 否 | 只用于筛选显示，不能作为完整性判定条件 |

固定表加载或手动粘贴解析完成后必须显示可多选的单号清单；后台只读状态查询和
手动刷新不得锁定该列表，也不得自动提交全部任务进入写流程。用户确认的单号集合
是后续资产筛选、SVN 更新和迁移的上层范围。Jira 版本登记属于中间信息，SVN
资产证据返回前不得显示绿色完成。

工具应自动验证每个本地目录的 SVN URL、仓库 UUID、工作副本根目录和分支角色，
避免把开发主干与海外主干配置反向。

## 7. 标准工作流

### 7.1 建立任务

1. 用户粘贴包含一个或多个源 Jira/海外 Jira 单号的网页文本。
2. 工具从飞书合并表双向解析 SERIA/OSCOA，并识别国内迁移、纯海外、单提 OSOB
   或不合并路线。
3. 工具在后台批量读取国内和海外 Jira 状态及版本登记，并直接按单号查询国内
   trunk、海外 trunk、OSOB 的远端 SVN 日志。
4. 工具将三段提交按“模块 + 相对路径”对齐成资产树，目录显示完成数，资产显示
   各阶段最终动作和 revision；此步骤不依赖本地 SVN 工作区。
5. 无本地工作区时，远端结果缓存 5 分钟，并默认每 2 分钟自动刷新，也可调整为
   5 分钟；切换任务、进入写流程或退出程序时取消旧查询，避免过期结果覆盖当前任务。
6. 查询起点优先使用所选 Jira 中最早创建日期前 3 天，并受“最大回溯天数”限制；
   Jira 日期不可用时使用当前日期减最大回溯天数。
7. 映射缺失或一对多时要求人工确认；不合并任务阻止进入迁移流程。

国内 trunk → 国内 OB 路线不读取飞书映射表，只从粘贴内容提取 `SERIA-*`，并将
同一单号同时作为源提交和目标提交的关联键。该路线不查询海外三阶段远端状态。

### 7.2 更新工作区

1. 先从仓库日志只读发现所选单号涉及的精确文件清单。
2. 在任何 SVN 写操作前按模块和目录展示待处理文件，由用户选择本次更新与后续
   迁移范围；空选择视为取消，不执行更新。
3. 对所选源文件执行远端状态检查，只选择落后的文件；目标侧只选择已判定为“需更新”
   的路径。
4. 将候选文件折叠为最小父目录集合；新增、删除或状态失败时回退到最近存在目录，
   目录数量超过 IPC 上限时回退到对应模块根目录。
5. 优先通过本机 IPC 请求常驻 SVNmate 更新规划出的目录。
6. SVNmate 未运行时，由迁移核验助手直接调用 `svnmate_core`。
7. 检测到 SVNmate 正在运行但 IPC 不可用时阻断，不允许启动第二套更新任务。
8. Update 失败时执行 Cleanup，并只重试一次。
9. 有本地改动时使用保守冲突策略；产生冲突后立即阻断该模块。
10. 更新后只重新核验所选文件；没有落后路径时直接复用筛选后的首次核验结果。
11. 所有命令必须保存退出码、时间、目标路径和错误输出。

### 7.3 扫描源单

1. 从 SVN 仓库日志中查询所有提交说明包含源单号的记录。
2. 解析版本号、作者、时间、动作、节点类型、复制来源和仓库路径。
3. 按最终动作整理有效文件；删除文件不能被静默过滤。
4. 将源仓库路径映射为模块内相对路径和目标仓库路径。
5. 生成不可变的“源清单快照”，显示本次扫描覆盖的版本范围。

### 7.4 执行迁移

1. 工具对所有选中任务统一生成源清单，不按 Jira 重复扫描工作副本。
2. 在更新工作副本前，将待处理文件按模块和目录展示；目录节点支持全选、清空和
   部分选择。只把用户勾选文件所在的必要目录交给 SVNmate 更新，未选文件不进入
   本次核验、迁移和提交范围。
3. 将所选范围写入源清单快照。迁移开始时直接复用该选择，只检查快照后新增的源
   提交和目标工作区状态，不重复要求选择；纯核验入口没有选择范围时，迁移前仍
   显示 `/Game/...` 资源目录树。
4. 源快照 revision 必须覆盖完整扫描已经读取的所有匹配提交，包括目录项和
   externals，不能仅使用工作副本根目录的 mixed revision。
5. 发现源单新增提交或工作区映射变化时要求重新完整核验。
6. 对选中的 `.uasset/.umap` 一次调用运行中 UE 的
   `SeriaMigrateInfo.migrate_by_package_names`。
7. 调用前校验当前 UE 工程和 `BranchContentPath` 与所选工作区一致。
8. 迁移后只刷新快照内目标文件的 SVN 状态；检测到本地改动后，对应文件转为
   “待提交”，不重复读取源、目标完整日志。
9. 表格、删除项和归属不明确的共享文件转人工处理，不执行自动覆盖。
10. 界面实时显示当前阶段已用时间；完成后汇总预检、UE 迁移、目标扫描、等待
    提交、增量复核及总耗时。

### 7.5 提交与复核

1. 工具按海外单号生成提交说明，并可打开 TortoiseSVN 提交窗口。
2. 打开提交窗口不改变任务状态。
3. 用户提交后，工具从核验快照的目标 revision 起增量查询新提交，并重新读取
   快照内目标文件状态。
4. 工具将每个目标提交与清单文件逐项关联。
5. 完成前从源快照 revision 增量检查源单；若出现新源提交，清单失效并提示
   重新完整核验。
6. 海外 OB 流程必须在国内到海外 trunk 的最终复核通过后，才继续执行
   海外 trunk 到 OSOB；第一阶段失败或未提交时停止。
7. 国内 OB 流程只执行国内 trunk 到国内 OB 的单阶段迁移；提交窗口关闭后用同一
   `SERIA-*` 重新查询国内 OB 目标提交并逐文件复核。

## 8. 文件级判定规则

下表“目标单号”在海外路线是 OSCOA，在国内 OB 路线是同一 SERIA。
任何已完成判定都要求工作副本不落后于已验证提交，否则先标“需更新”。

| 目标证据 | 本地 SVN 状态 | 判定 |
| --- | --- | --- |
| 目标单号提交包含该路径 | normal/clean | 已完成 |
| 本批次其他目标单号提交包含该路径 | normal/clean | 已提交，视为已完成 |
| 目标单号提交包含该路径 | modified/added/deleted/replaced | 待提交，目标仍有后续改动 |
| 无目标单号提交 | modified/added/deleted/replaced | 待提交 |
| 无目标单号提交 | normal/clean | 未迁移 |
| 其他单号提交包含该路径 | normal/clean | 需确认，不能自动归属本任务 |
| 任意 | conflicted/obstructed/incomplete | 阻断 |
| 目标路径或父目录未版本化 | unversioned | 待添加并提交 |
| 源动作是删除，目标已按目标单号删除 | 路径不存在且父目录正常 | 已完成 |
| 源文件在本任务后被其他 revision 删除 | 源路径不存在且有后续删除证据 | 源已删除，当前单无需迁移 |

后续人工豁免必须记录原因、操作者和时间，并在源清单变化时失效；当前没有该持久
任务库和 `WAIVED` 状态，不得按此计划放行。

## 9. 目录与提交完整性

用户要求的“对应文件夹已经完成提交”按以下方式判断：

1. 对每个预期文件执行精确状态检查。
2. 对新增文件逐级检查到工作副本根目录，确认所有新增父目录都已纳入版本控制。
3. 对最小公共父目录执行状态扫描，区分本任务改动和无关改动。
4. 通过目标仓库日志确认海外单号的提交，而不是只检查本地目录是否干净。
5. 目标工作副本版本落后于对应提交时，先标记“需更新”，不能直接显示完成。

无关本地改动需要提示，但不应被自动加入本任务的提交列表。

## 10. 特殊文件规则

| 类型 | 处理方式 |
| --- | --- |
| `.uasset` / `.umap` | 交给 `SeriaMigrate` 执行；当前核验 SVN 直接清单，实际依赖清单接入仍是计划 |
| `.csv` / `.xlsm` / `.xml` | 标记为表格迁移，允许接入 `SeriaTableUtil`，默认要求人工复核 |
| `.lua` 及普通文本 | 按相对路径核验本地修改和目标提交 |
| 删除 | 必须验证目标删除提交，不能从预期清单中移除 |
| 重命名/复制 | 同时展示来源与目标路径，无法稳定映射时转人工确认 |
| SVN external | 使用该节点自身的 SVN URL 和工作副本根，不能按父目录字符串拼接 |
| 被现有工具忽略的 JSON/MD/YAML | 在核验清单中保留，并标记迁移策略待确认 |

## 11. 异常与恢复

- SVN CLI 不存在：阻断，并给出 TortoiseSVN 命令行组件检查入口。
- SVN 凭据失效：阻断当前网络步骤，保留已生成清单。
- Update 失败：Cleanup 后重试一次；仍失败则阻断对应模块。
- 工作副本冲突：不自动解决，不自动 revert。
- 目标路径映射失败：显示源仓库路径、模块和失败原因。
- Jira 服务不可用：允许用户输入查询日期或起始版本后继续。
- 找不到源提交：区分“格式错误”“查询范围不足”“确实无提交”。
- 迁移后源单新增提交：将任务恢复为“有新增内容”。
- 同一文件被多个任务修改：显示交叉任务，要求人工归属。
- 用户取消 TortoiseSVN 提交：保持“待提交”，不视为错误。

## 12. 任务状态

| 状态 | 进入条件 |
| --- | --- |
| 待准备 | 单号或工作区尚未通过校验 |
| 更新中 | 正在更新源/目标工作副本 |
| 可迁移 | 已生成有效源清单 |
| 迁移中 | 已开始观察目标改动 |
| 待提交 | 至少一个预期文件存在未提交改动 |
| 待补迁 | 至少一个预期文件没有目标证据 |
| 需确认 | 只剩人工判定项 |
| 已完成 | 所有必需项完成，且最终源扫描无新增提交 |
| 已阻断 | 存在冲突、命令失败或路径错误 |

## 13. 桌面端信息架构

布局、主题、控件、DPI 与反馈统一维护在
[MigrationGuard DESIGN](../migration_guard/DESIGN.md)，本文只保留业务要求：

- 单一粘贴入口、四条明确路线，路径/固定表/扫描策略在设置中维护。
- 任务与资产视图复用同一批证据；筛选和搜索不能改变处理范围。
- 无工程资产树显示三阶段提交，不代表本地已干净；Jira 中间态不得标绿。
- 长任务仍可浏览结果和详情，阶段进度写到受影响行，不清空整表。
- 同一工作区不并发写，确认范围和最终提交复核不可因 UI 简化而省略。

## 14. 当前交付范围

### 已实现

- 工作区配置与 SVN 身份校验。
- 常驻 SVNmate IPC 调用，以及未运行时的 `svnmate_core` 回退。
- 复用 SVNmate 的 Update -> Cleanup -> 单次重试流程。
- 源/海外单号的 SVN XML 日志扫描。
- `res`、`doc`、`bin` 和 externals 的路径映射。
- 文件级状态表和完整性结论。
- 打开 TortoiseSVN 提交窗口。
- 提交后重新核验。
- 多单批量迁移和 Trunk -> OB 自动两阶段流程。
- 更新前资产范围选择，以及更新、迁移、提交和第二阶段之间的范围复用。
- 国内 trunk -> 国内 OB 的 SERIA 单阶段本地迁移与复核。
- 无工程 Jira/远端 SVN 资产树、5 分钟缓存、可取消查询和 2/5 分钟自动刷新。

### 尚未实现

- 本地任务历史、人工豁免记录与 SQLite 任务库。
- `commit_info.json` 导入及 schema v2 迁移清单。
- Markdown 报告导出。
- 同路径被其他单号后续修改的逐文件源漂移提示；当前已有源单新增提交失效门禁。
- 表格语义差异与 UE 依赖资源的精确 Jira 归属。
- 自动提交、自动 revert、自动解决冲突。
- 二进制 Unreal 资产语义对比。
- 直接修改 Jira 状态。

## 16. MVP 验收标准

以下是完整目标验收口径；涉及任务历史、`commit_info.json`、Markdown 报告和源漂移
的条目需结合第 14 节“尚未实现”状态判断，不能据此宣称当前版本已经全部交付。

1. 给定一个包含多次提交、多人提交的源单号，清单不得因作者筛选而漏文件。
2. 目标文件未改、未提交时必须显示“未迁移”，不能显示完成。
3. 目标文件已改但未提交时必须显示“待提交”。
4. 仅打开并关闭提交窗口后，状态仍为“待提交”。
5. 使用海外单号提交并刷新后，相关文件显示目标版本号和“已完成”。
6. 只迁移清单的一部分时，任务显示“待补迁”并列出具体文件。
7. 新增文件的父目录未 `svn add` 时必须提示。
8. 最终核验时源单新增提交，任务自动退出“已完成”。
9. externals 中的文件使用自身仓库路径正确核验。
10. 全流程不执行自动 commit、revert 或冲突解决。

## 17. 当前默认决策

- 正确目标单号是完成证据：海外用 OSCOA，国内 OB 用相同 SERIA，不混用路线。
