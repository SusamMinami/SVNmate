# 海外迁移核验助手：需求说明

## 1. 文档状态

- 产品暂定名：迁移核验助手
- 运行平台：Windows 桌面端
- 当前阶段：需求基线 / MVP 设计
- 目标流程：开发主干 `trunk` -> 海外 `trunk`

## 2. 问题定义

组内日常迁移同时跨越 Jira、SVN、Unreal Editor 和人工提交窗口。现有工具可以按
Jira 单号找到资源并发起迁移，但无法稳定回答下面三个问题：

1. 源单实际涉及哪些文件和提交？
2. 每个源文件在目标工作副本中是否已经产生对应变更？
3. 这些变更是否已经使用正确的海外单号提交到目标 SVN？

因此，“工作副本干净”不能直接视为迁移完成。它也可能表示文件从未迁移；同样，
“已打开 TortoiseSVN 提交窗口”也不能证明提交已经成功。

## 3. 产品目标

工具需要为每个迁移单建立一份可重复核验的迁移清单，并把结论归纳为：

- **未迁移**：源文件存在，但目标没有本地变更，也没有目标提交证据。
- **待提交**：目标已经产生本地修改、新增、删除或替换，但尚未提交。
- **已完成**：目标存在对应单号的提交记录，且目标工作副本没有该文件的遗留改动。
- **需确认**：检测到同路径的其他提交、无需迁移、路径改名、外部目录等无法自动判定的情况。
- **阻断**：工作副本冲突、路径映射失败、SVN 命令失败或源清单不可信。

最终只有在所有必需项均为“已完成”或经过人工记录的“无需迁移”时，任务才可标记
为完成。

## 4. 非目标

MVP 不做以下事情：

- 不自动点击确认并提交 SVN。
- 不自动解决 SVN 冲突。
- 不替换 `SeriaMigrateInfo` 的资源迁移实现；桌面工具只负责批量编排调用。
- 不承诺比较两个 `.uasset` 的语义是否完全一致。
- 不根据“文件存在”或“目标目录是干净的”推断迁移成功。
- 不修改现有开发主干或海外分支的资源。

## 5. 使用角色

主要用户是负责把开发主干内容迁移到海外分支的策划、程序或资源维护人员。用户需要
在一次操作中处理 `res`、`doc`、`bin` 中的一个或多个模块，并可能同时面对
SVN externals、多个源提交、多人提交和同一文件的后续修改。

## 6. 核心输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 待识别 Jira 单号 | 是 | 可输入 `SERIA-12345` 或 `OSCOA-67890` |
| 海外 Jira 单号 | 自动或手填 | 优先从飞书合并表解析；完成核验时必须存在 |
| 飞书固定表 | 是 | 分别配置 Trunk/海外 OB 工作簿，自动读取最新可见页签 |
| Jira 只读状态 | 自动 | 读取国内/海外工单状态、创建时间和版本登记；不要求本地工程 |
| 工作区配置 | 精确核验时必填 | 国内 trunk、海外 trunk、海外 OB 三组 SVN 工作副本 |
| 查询起点 | 自动，可调整 | 优先读取 Jira 创建时间；失败时使用用户设置的日期或版本号 |
| 作者 | 否 | 只用于筛选显示，不能作为完整性判定条件 |

工具应自动验证每个本地目录的 SVN URL、仓库 UUID、工作副本根目录和分支角色，
避免把开发主干与海外主干配置反向。

## 7. 标准工作流

### 7.1 建立任务

1. 用户粘贴包含一个或多个源 Jira/海外 Jira 单号的网页文本。
2. 工具从飞书合并表双向解析 SERIA/OSCOA，并识别国内迁移、纯海外、单提 OSOB
   或不合并路线。
3. 工具在后台批量读取国内和海外 Jira 状态及版本登记，立即展示每个任务当前位于
   国内 trunk、海外 trunk 或海外 OB；此步骤不依赖本地 SVN 工作区。
4. 映射缺失或一对多时要求人工确认；不合并任务阻止进入迁移流程。
5. 工具创建本地迁移任务，记录工作区配置和开始时间。

### 7.2 更新工作区

1. 先从仓库日志只读发现所选单号涉及的精确文件清单。
2. 对源文件执行远端状态检查，只选择落后的文件；目标侧只选择已判定为“需更新”
   的路径。
3. 将候选文件折叠为最小父目录集合；新增、删除或状态失败时回退到最近存在目录，
   目录数量超过 IPC 上限时回退到对应模块根目录。
4. 优先通过本机 IPC 请求常驻 SVNmate 更新规划出的目录。
5. SVNmate 未运行时，由迁移核验助手直接调用 `svnmate_core`。
6. 检测到 SVNmate 正在运行但 IPC 不可用时阻断，不允许启动第二套更新任务。
7. Update 失败时执行 Cleanup，并只重试一次。
8. 有本地改动时使用保守冲突策略；产生冲突后立即阻断该模块。
9. 更新后重新执行完整核验；没有落后路径时直接复用第一次核验结果。
10. 所有命令必须保存退出码、时间、目标路径和错误输出。

### 7.3 扫描源单

1. 从 SVN 仓库日志中查询所有提交说明包含源单号的记录。
2. 解析版本号、作者、时间、动作、节点类型、复制来源和仓库路径。
3. 按最终动作整理有效文件；删除文件不能被静默过滤。
4. 将源仓库路径映射为模块内相对路径和目标仓库路径。
5. 生成不可变的“源清单快照”，显示本次扫描覆盖的版本范围。

### 7.4 执行迁移

1. 工具对所有选中任务统一生成源清单，不按 Jira 重复扫描工作副本。
2. 将去重后的可迁移资源按 `/Game/...` 目录树展示；目录节点支持全选、清空和
   部分选择，由用户按文件夹或具体资源选择本次迁移内容。
3. 对选中的 `.uasset/.umap` 一次调用运行中 UE 的
   `SeriaMigrateInfo.migrate_by_package_names`。
4. 调用前校验当前 UE 工程和 `BranchContentPath` 与所选工作区一致。
5. 迁移后统一扫描目标工作副本；检测到本地改动后，对应文件转为“待提交”。
6. 表格、删除项和归属不明确的共享文件转人工处理，不执行自动覆盖。

### 7.5 提交与复核

1. 工具按海外单号生成提交说明，并可打开 TortoiseSVN 提交窗口。
2. 打开提交窗口不改变任务状态。
3. 用户提交后点击刷新；工具重新查询目标仓库日志和工作副本状态。
4. 工具将每个目标提交与清单文件逐项关联。
5. 完成前再次扫描源单；若出现新源提交，清单失效并提示补迁。
6. 海外 OB 流程必须在国内到海外 trunk 的最终复核通过后，才继续执行
   海外 trunk 到 OSOB；第一阶段失败或未提交时停止。

## 8. 文件级判定规则

| 目标证据 | 本地 SVN 状态 | 判定 |
| --- | --- | --- |
| 海外单号提交包含该路径 | normal/clean | 已完成 |
| 本批次其他海外单号提交包含该路径 | normal/clean | 已提交，视为已完成 |
| 海外单号提交包含该路径 | modified/added/deleted/replaced | 待提交，目标仍有后续改动 |
| 无海外单号提交 | modified/added/deleted/replaced | 待提交 |
| 无海外单号提交 | normal/clean | 未迁移 |
| 其他单号提交包含该路径 | normal/clean | 需确认，不能自动归属本任务 |
| 任意 | conflicted/obstructed/incomplete | 阻断 |
| 目标路径或父目录未版本化 | unversioned | 待添加并提交 |
| 源动作是删除，目标已按海外单号删除 | 路径不存在且父目录正常 | 已完成 |
| 用户批准无需迁移 | 任意非冲突状态 | 无需迁移 |

“无需迁移”必须填写原因、操作者和时间，并保存在任务记录中。重新扫描发现源文件又有
新提交时，原人工结论自动过期。

## 9. 目录与提交完整性

用户要求的“对应文件夹已经完成提交”按以下方式判断：

1. 对每个预期文件执行精确状态检查。
2. 对新增文件逐级检查到工作副本根目录，确认所有新增父目录都已纳入版本控制。
3. 对最小公共父目录执行状态扫描，区分本任务改动和无关改动。
4. 通过目标仓库日志确认海外单号的提交，而不是只检查本地目录是否干净。
5. 目标工作副本版本落后于对应提交时，先标记“需更新”，不能直接显示完成。

无关本地改动需要提示，但不应被自动加入本任务的提交列表。

## 10. 特殊文件规则

| 类型 | 处理方式 |
| --- | --- |
| `.uasset` / `.umap` | 交给 `SeriaMigrate` 执行；核验直接文件及实际迁移清单 |
| `.csv` / `.xlsm` / `.xml` | 标记为表格迁移，允许接入 `SeriaTableUtil`，默认要求人工复核 |
| `.lua` 及普通文本 | 按相对路径核验本地修改和目标提交 |
| 删除 | 必须验证目标删除提交，不能从预期清单中移除 |
| 重命名/复制 | 同时展示来源与目标路径，无法稳定映射时转人工确认 |
| SVN external | 使用该节点自身的 SVN URL 和工作副本根，不能按父目录字符串拼接 |
| 被现有工具忽略的 JSON/MD/YAML | 在核验清单中保留，并标记迁移策略待确认 |

## 11. 异常与恢复

- SVN CLI 不存在：阻断，并给出 TortoiseSVN 命令行组件检查入口。
- SVN 凭据失效：阻断当前网络步骤，保留已生成清单。
- Update 失败：Cleanup 后重试一次；仍失败则阻断对应模块。
- 工作副本冲突：不自动解决，不自动 revert。
- 目标路径映射失败：显示源仓库路径、模块和失败原因。
- Jira 服务不可用：允许用户输入查询日期或起始版本后继续。
- 找不到源提交：区分“格式错误”“查询范围不足”“确实无提交”。
- 迁移后源单新增提交：将任务恢复为“有新增内容”。
- 同一文件被多个任务修改：显示交叉任务，要求人工归属。
- 用户取消 TortoiseSVN 提交：保持“待提交”，不视为错误。

## 12. 任务状态

| 状态 | 进入条件 |
| --- | --- |
| 待准备 | 单号或工作区尚未通过校验 |
| 更新中 | 正在更新源/目标工作副本 |
| 可迁移 | 已生成有效源清单 |
| 迁移中 | 已开始观察目标改动 |
| 待提交 | 至少一个预期文件存在未提交改动 |
| 待补迁 | 至少一个预期文件没有目标证据 |
| 需确认 | 只剩人工判定项 |
| 已完成 | 所有必需项完成，且最终源扫描无新增提交 |
| 已阻断 | 存在冲突、命令失败或路径错误 |

## 13. 桌面端信息架构

主窗口固定面向桌面宽屏，核心区域优先给文件清单，不使用大面积欢迎页。

### 顶部命令栏

- 当前工作区配置
- 源单号
- 海外单号
- 更新工作区
- 扫描/刷新
- 设置

### 状态汇总栏

固定宽度展示总数、未迁移、待提交、已完成、需确认、阻断，切换状态时不改变布局。

### 文件清单

| 列 | 内容 |
| --- | --- |
| 状态 | 图标与短标签 |
| 模块 | res/doc/bin/external |
| 相对路径 | 可横向滚动，双击复制 |
| 源证据 | 版本号、动作、提交数 |
| 目标本地状态 | modified/added/normal 等 |
| 目标提交 | 海外版本号或“无证据” |
| 操作 | 打开目录、查看日志、标记无需迁移 |

选择一行后在右侧固定宽度详情栏展示完整路径、源提交、目标提交、状态解释和人工备注。
筛选页签和详情栏均保持稳定尺寸，避免文件状态刷新时界面抖动。

### 无工程 Jira 进度

单号解析完成后，文件清单区域先显示任务级 Jira 进度表：

| 列 | 内容 |
| --- | --- |
| 当前阶段 | 国内 trunk、海外 trunk、海外 OB 或状态未知 |
| 一致性 | 国内已登记但海外缺失、两侧 trunk 一致或版本异常 |
| 任务 | 海外标题或源标题 |
| 国内 Jira | SERIA 单号及当前状态 |
| 海外 Jira | OSCOA 单号及当前状态 |
| 版本登记 | 海外 trunk 与 OSOB 登记情况 |

该视图供没有工程工作区的项目管理员使用。Jira 版本登记表示流程记录，不等同于
文件级 SVN 提交证据；有工作区的用户可从同一行继续执行精确核验。

### 底部状态栏

展示当前 SVN 操作、工作副本版本、最后刷新时间和日志入口。长任务在后台线程执行，
界面始终可操作，但同一工作区不允许并发执行多个写操作。

## 14. MVP 范围

MVP 必须包含：

- 工作区配置与 SVN 身份校验。
- 常驻 SVNmate IPC 调用，以及未运行时的 `svnmate_core` 回退。
- 复用 SVNmate 的 Update -> Cleanup -> 单次重试流程。
- 源/海外单号的 SVN XML 日志扫描。
- `res`、`doc`、`bin` 和 externals 的路径映射。
- 文件级状态表和完整性结论。
- 现有 `commit_info.json` 导入。
- 打开 TortoiseSVN 提交窗口。
- 提交后重新核验。
- 本地任务历史和可导出的 Markdown/JSON 报告。

MVP 暂不包含：

- 自动提交、自动 revert、自动解决冲突。
- 二进制 Unreal 资产语义对比。
- 直接修改 Jira 状态。

## 15. 后续版本

- P1：SeriaMigrate 输出实际依赖迁移清单和迁移批次 ID。
- P1：表格迁移差异的专用核验。
- P1：SVNmate 工具模块安装与更新入口。
- P1：[已完成] Jira 状态只读同步和无工程迁移进度列表。
- P2：团队级迁移记录汇总与重复迁移检测。

## 16. MVP 验收标准

1. 给定一个包含多次提交、多人提交的源单号，清单不得因作者筛选而漏文件。
2. 目标文件未改、未提交时必须显示“未迁移”，不能显示完成。
3. 目标文件已改但未提交时必须显示“待提交”。
4. 仅打开并关闭提交窗口后，状态仍为“待提交”。
5. 使用海外单号提交并刷新后，相关文件显示目标版本号和“已完成”。
6. 只迁移清单的一部分时，任务显示“待补迁”并列出具体文件。
7. 新增文件的父目录未 `svn add` 时必须提示。
8. 最终核验时源单新增提交，任务自动退出“已完成”。
9. externals 中的文件使用自身仓库路径正确核验。
10. 全流程不执行自动 commit、revert 或冲突解决。

## 17. 当前默认决策

- 海外单号是“已完成”判定的必需证据；未填写时不允许绿色完成。
- 第一版支持多个可命名工作区配置，默认聚焦海外 trunk，不硬编码本机盘符。
- 提交仍由 TortoiseSVN 完成人工审核，工具只负责生成选择范围并在提交后验证。
- 作者筛选只影响视图，不影响源单完整性。
- 路径级提交证据是 MVP 的完成口径；资产内容语义一致性另行扩展。
