# 配置关系检索器设计

- 日期：2026-07-28
- 状态：已确认
- 工具暂定名：配置关系检索器
- EXE 暂定名：`ConfigLinker.exe`

## 1. 背景

配置工作经常需要在以下三张表之间往返查询：

- `m目标物表.csv`
- `NPC表.csv`
- `m模型资源表.csv`

核心关系为：

```text
目标物 ID -> NPC ID -> 模型资源 ID
```

同时需要支持反向查询：

```text
模型资源 ID -> 使用该资源的 NPC -> 使用这些 NPC 的目标物
NPC ID -> 使用该 NPC 的全部目标物
```

目标是通过一个只读桌面工具，输入任意一种 ID 后，一次性看到完整关系和必要的辅助信息。

## 2. 已确认的数据事实

第一版只读取：

```text
C:\trunk\doc\csvdir
```

三张 CSV 均为 UTF-8 BOM，且使用双表头：

- 第 1 行：成员映射
- 第 2 行：中文说明

实际字段关系：

```text
MissionPosition.NPCID -> NPC.id
NPC.resource_id -> Model.id
```

需要展示的字段：

| 对象 | 默认字段 | 展开字段 |
| --- | --- | --- |
| 目标物 | 目标物 ID、类型、描述、NPC ID | CSV 行号及其他诊断信息 |
| NPC | NPC ID、备注、名称、资源 ID | CSV 行号及其他诊断信息 |
| 模型资源 | 资源 ID、配置路径 | 自动生成路径、CSV 行号 |

CSV 与 Excel 列位存在偏移，因为 Excel 首列“版本”不会导出到 CSV。程序不得直接把 Excel 的 B/C/F 列号当作 CSV 列号。

部分辅助字段没有第 1 行成员名：

- 目标物“类型”和“描述”按第 2 行中文表头识别。
- 模型“配置路径”按第 2 行说明与表结构识别。
- 主键和外键优先按第 1 行成员名识别。

## 3. 产品范围

### 3.1 第一版目标

- 独立 Windows 桌面 EXE。
- 沿用 SVNmate 的 Python、Tkinter/ttk、PyInstaller 技术路线。
- 使用 Metro 风格、Segoe UI、扁平卡片和蓝色强调色。
- 支持目标物 ID、NPC ID、模型资源 ID 的精确查询。
- 支持正向和反向关系展开。
- 支持点击任意结果 ID，将其切换为新的查询中心。
- 支持逐级返回之前的查询。
- 启动时读取 CSV，并提供手动重新加载。
- 只读配置，不修改 CSV，不运行导表或校验脚本。

### 3.2 第一版不做

- 不读取 `csvspecial`。
- 不直接读取或保存 `.xlsm`。
- 不做名称模糊搜索。
- 不做批量 ID 查询。
- 不做自由拖拽的知识图谱画布。
- 不自动监控 CSV 文件变化。
- 不联网。

## 4. 界面设计

### 4.1 页面结构

窗口分为四个区域：

1. 标题与数据状态
2. 中央搜索区
3. 固定三段关系图
4. 行内提示与诊断区

中央搜索区：

```text
[目标物 ID / NPC ID / 模型资源 ID] [输入 ID] [搜索]
```

顶部操作：

```text
[返回上一步] [重新加载] [选择数据目录] [复制诊断信息]
```

关系图固定为：

```text
[目标物]  ->  [NPC]  ->  [模型资源]
```

当前查询类型对应的卡片使用蓝色高亮。卡片之间用固定连线表达关系，不使用自由画布。

### 4.2 结果卡片

每张卡片包含：

- 标题与结果总数
- 当前主记录
- 可滚动的关联记录列表
- “展开详情/收起详情”
- 结果过多时的“加载更多”

所有结果 ID 使用可点击样式。点击 ID 后：

1. 当前查询状态压入历史栈。
2. 被点击的 ID 成为新的查询中心。
3. 三张关系卡片重新计算并显示。
4. “返回上一步”变为可用。

历史栈支持连续回退，不限于一次返回。第一条查询没有历史时，按钮置灰。

### 4.3 查询展开规则

搜索目标物 ID：

- 显示命中的目标物。
- 显示目标物关联的 NPC。
- 显示 NPC 关联的模型资源。
- 折叠显示使用同一 NPC 的其他目标物。

搜索 NPC ID：

- 显示命中的 NPC。
- 显示使用该 NPC 的全部目标物。
- 显示 NPC 关联的模型资源。
- 折叠显示使用同一资源的其他 NPC。

搜索模型资源 ID：

- 显示命中的模型资源。
- 显示使用该资源的全部 NPC。
- 显示这些 NPC 对应的全部目标物。

## 5. 技术架构

第一版保持小型、可合并的模块结构：

- UI 层：窗口、搜索区、关系卡片、状态提示、历史导航。
- CSV 加载层：编码处理、标准 CSV 解析、双表头解析、字段校验。
- 数据仓库层：保存记录和反向索引。
- 查询服务层：根据查询类型和 ID 生成统一结果模型。
- 配置层：保存用户选择的数据目录。

只使用必要依赖。CSV 使用标准解析器处理引号、逗号和多行字段，不使用手工字符串切分。

## 6. 内存索引

加载后建立以下索引：

```text
targets_by_id:        目标物 ID -> 目标物记录列表
targets_by_npc_id:    NPC ID -> 目标物记录列表
npcs_by_id:           NPC ID -> NPC 记录列表
npcs_by_resource_id:  资源 ID -> NPC 记录列表
resources_by_id:      资源 ID -> 模型资源记录列表
```

索引值使用列表，不假设 ID 永远唯一。若出现重复 ID，所有记录都保留并显示 CSV 行号，不允许后加载记录静默覆盖前一条。

## 7. 加载与刷新

默认目录为 `C:\trunk\doc\csvdir`，允许用户选择其他目录，并将选择结果保存在工具自己的配置文件中。

启动流程：

1. 检查三张文件是否存在。
2. 使用 UTF-8 BOM 兼容方式读取。
3. 解析双表头。
4. 校验必需字段。
5. 构建临时记录和索引。
6. 全部成功后，原子替换当前内存数据。

手动刷新采用同一流程。若刷新失败：

- 保留上一份成功加载的数据。
- 顶部显示“刷新失败，当前仍使用旧数据”。
- 诊断信息包含失败文件和原因。

## 8. 异常处理

状态分三级：

- 绿色：三张表加载成功，显示记录数和加载时间。
- 黄色：主记录存在，但关联的 NPC 或资源缺失。
- 红色：目录错误、文件缺失、编码错误或必需表头缺失。

以下情况使用行内提示，不弹出阻断式窗口：

- 未输入 ID
- ID 不是整数
- 查无结果
- 某段关联未配置

关联缺失时仍显示已找到的主记录，不因后续链路断开而清空整个结果。

## 9. 性能设计

三张 CSV 总体积较小，启动时一次加载并建立哈希索引。查询复杂度主要取决于实际关联结果数量，不在每次搜索时重新扫描整张表。

单个卡片默认最多渲染 200 条记录，并显示总数。用户点击“加载更多”后继续追加，避免大量同资源 NPC 导致界面卡顿。

## 10. 验收测试

至少覆盖：

- 目标物 ID 精确查询及完整链路。
- NPC ID 精确查询及反向目标物列表。
- 资源 ID 精确查询及反向 NPC、目标物列表。
- 同 NPC 多目标物。
- 同资源多 NPC。
- 点击目标物、NPC、资源 ID 切换查询中心。
- 连续切换后逐级返回上一步。
- UTF-8 BOM 和中文字段读取。
- 带引号、逗号和换行的 CSV 字段读取。
- 重复 ID 不被覆盖。
- 主记录存在但关联缺失。
- 文件缺失和表头变化。
- 刷新失败后旧数据仍可查询。
- 打包后的 EXE 在无 Python 环境下启动。
