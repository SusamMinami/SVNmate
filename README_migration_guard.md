# 迁移核验助手

用于检查开发主干 Jira 单涉及的 SVN 文件，确认海外目标工作副本是否已修改，以及
是否已有海外 Jira 单号对应的提交记录。

## 启动

源码运行：

```bat
run_migration_guard.bat
```

打包：

```bat
build_migration_guard.bat
```

生成文件：

```text
dist\MigrationGuard.exe
```

SVNmate 会自动识别该文件，并在“工具模块”中显示“迁移核验助手”。

飞书单号识别依赖本机 `lark-cli` 的用户登录态；SVN 核验依赖 TortoiseSVN 命令行
组件或 `svn.exe`。

## 使用

1. 在右上角设置中一次配置国内 trunk、海外 trunk、海外 OB 三个工作区，以及
   Trunk/海外 OB 两个固定飞书工作簿。
2. 点击“Trunk 表”或“海外 OB 表”。工具会自动读取该工作簿最新的可见页签，
   并切换到正确的工作区路线。
3. 也可以把网页中的一行或多行任务直接粘贴到单号框；工具会批量提取
   `SERIA-*`/`OSCOA-*`，并在下方分别显示源单号和海外单号。
4. 选择需要检查的 `res`、`doc`、`bin`，通常保持 externals 开启。
5. 在任务表选择任务后点击“核验选中”或双击任务，工具自动开始只读核验。
6. 左下主表会先实时显示扫描步骤，再切换为文件级核验结果。
7. “更新并核验”会优先请求常驻 SVNmate 更新全部选中工作副本，然后执行核验。
8. 核验后点击“批量迁移”，先在 `/Game/...` 资产目录树中按文件夹或资源选择
   本次要迁移的内容；工具随后统一预检、一次调用 UE 迁移、按海外 Jira 准备
   TortoiseSVN 提交窗口，并在窗口关闭后统一复核。
9. 海外 OB 表中的国内任务会在国内 → 海外 trunk 复核通过后，自动切换工作区并
   继续海外 trunk → OSOB；纯海外任务直接执行第二阶段。
10. 提交目标文件后也可使用“复核”刷新提交状态。

默认固定表（可在设置中分别修改）：

```text
https://bytedance.larkoffice.com/wiki/N7YJwiV4FivSiuko5FCc90O0nEc?sheet=kGEBNH
```

固定表链接可以带旧的 `sheet` 参数；读取时会自动定位工作簿中排序最前的可见页签。
标准国内迁移行使用 `OSCOA完整标题&&&&SERIA完整标题`；工具还会识别“纯海外单子”、
“单提OSOB”和“不合并”分段。两个工作簿分别缓存，在线读取失败时使用各自最近一次
成功缓存。

## 更新

MigrationGuard 使用独立的 `migration-guard-latest` 发布通道，版本号见
`migration_guard/VERSION`。SVNmate 的工具模块区域可独立安装、检查和更新，不与
SVNmate 主程序版本绑定。

## 状态

- **未迁移**：目标没有本地修改，也没有海外单号提交证据。
- **待提交**：目标存在 modified/added/deleted/replaced 等本地改动。
- **已完成**：海外单号提交已覆盖该路径，且没有遗留本地修改。
- **已提交**：本批次其他海外单号已经提交同一路径，不再重复迁移。
- **需更新**：目标工作副本落后于仓库状态。
- **需确认**：删除或提交动作无法自动确认。
- **阻断**：冲突、路径映射或 SVN 命令失败。

双击文件行可复制目标路径，右侧详情显示源版本、作者、目标版本和完整路径。结果可
导出为 JSON。

批量迁移通过 `127.0.0.1:12031` 连接运行中 UE 的 OmniMcpCore。执行前会校验
当前 UE 工程和 `BranchContentPath`；已完成或已待提交的资源不会重复迁移。表格、
删除项及跨 Jira 共享文件保留为人工处理项，工具不会自动提交或覆盖这些内容。
