# 迁移核验助手

当前版本：`1.0.5`

用于检查开发主干 Jira 单涉及的 SVN 文件，确认海外目标工作副本是否已修改，以及
是否已有海外 Jira 单号对应的提交记录。

## 启动

源码运行：

```bat
run_migration_guard.bat
```

打包：

```bat
build_migration_guard.bat
```

生成文件：

```text
dist\MigrationGuard.exe
```

可执行文件使用独立的 MigrationGuard 三阶段迁移核验图标，不再复用 SVNmate
图标。SVNmate 会自动识别该文件，并在“工具模块”中显示“迁移核验助手”。
本地构建脚本会同时把 `migration_guard\VERSION` 复制到 `dist\VERSION`，因此
直接重新运行 `build_migration_guard.bat` 即可覆盖本仓库 `dist` 中的已安装版本。

飞书单号识别依赖本机 `lark-cli` 的用户登录态。Jira 项目进度和远端资产树不要求
本地工程，但需要 `svn.exe` 及对应仓库的只读权限；工作副本精确核验依赖本地
TortoiseSVN/SVN 配置。

## v1.0.5 要点

- “更新并复核”在任何 SVN 写入前先展示本批次文件树，由用户选择实际处理范围；
  空选择不会执行更新。
- SVNmate 只更新所选文件涉及的最小目录，后续核验、UE 迁移、提交和 OSOB
  第二阶段持续复用同一范围，不再重复选择或把未选文件带回流程。
- 源快照 revision 使用完整日志扫描中读取到的最高匹配版本，包含目录项与
  externals，避免以 mixed revision 作为不完整基线。
- 取消选择会回到可重试状态，选择窗口会区分更新与迁移用途，并明确显示待处理、
  已完成和人工文件范围。

## 使用

1. 在右上角设置中配置国内 trunk、海外 trunk、海外 OB，以及可选的国内 OB
   工作区；同时配置两个固定飞书工作簿、扫描范围、最大回溯天数和自动刷新频率
   （默认 2 分钟，可切换为 5 分钟）。`res`、`doc`、`bin`、`externals` 全部
   不选时按单据自动判断。四个工作区以 2×2 布局展示。
2. 点击标题右侧“合海外 Trunk”或“合海外 Trunk-OB”。工具会自动读取工作簿
   最近一张包含对应路线任务的可见页签，在按钮上显示实际页签日期，并切换到正确
   的工作区路线。若最新页签只有纯海外任务，“合海外 Trunk”会继续向前查找最近
   含国内到海外映射的页签，不再显示空表。加载完成后先停留在单号清单并预选全部
   可执行任务，同时后台只读查询 Jira 与远端 SVN 证据；查询期间仍可调整多选，
   也可点击“刷新状态”强制重查。点击“使用选中”只锁定后续资产选择、更新和迁移
   的单号范围。
3. 也可以把网页中的一行或多行任务直接粘贴到单号框；工具会批量提取
   `SERIA-*`/`OSCOA-*`，以相同方式显示可多选解析结果并自动只读检查状态。
   未选单号不会进入资产筛选和更新迁移；纯海外 OSCOA 会自动切换到海外 OB 路线。
   选择“国内 trunk → 国内 OB”时只提取 `SERIA-*`，源单号与目标单号相同，
   不读取飞书海外映射表。
4. Jira 结果仅作为中性“等待 SVN”过渡态，不显示绿色完成；最终颜色与状态以
   三套远端 SVN 的资产和提交证据为准。查询完成前后都可选择单号。
   主表默认进入“单号”页签，每个单号可展开查看对应资产；切换到“资产”页签后按
   模块和路径查看去重后的资产树，不要求本机存在 SVN 工作区。单号树使用
   `SER-*` / `OSC-*` 短格式并优先显示任务描述，右侧详情保留完整单号并按资产状态
   为关联单号着色。树节点过长时，悬停可查看完整文本。
5. 单号、资产和目录节点分别显示国内 trunk、海外 trunk、海外 OB 的 revision
   或完成数；
   “单号 / 资产”切换、主筛选“全部、待处理、已完成、阻断”、详细状态“更多”
   以及资产关键词搜索和进度条共用一行；搜索同时过滤资产路径及其关联单号。
   进度区显示上次刷新或复核时间。没有可用本地工作区时，状态会按设置频率自动
   刷新；点击“刷新状态”可立即绕过短期缓存。
6. 有本地工作区时主动作显示为“更新并复核”。存在待处理资产时右侧按钮显示
   “迁移”；全部完成后同一按钮自动切换为“复核”。扫描范围沿用设置中的 `res`、
   `doc`、`bin` 和 externals。
7. “更新并复核”先只读扫描单号涉及的文件，随后立即按目录树选择本次要处理的
   资产；`res`、`doc`、`bin` 和 externals 中的文件都可单独取消。确认前不会执行
   SVN update，空选择不能继续。
8. 确认后只检查所选源文件和目标文件的远端状态，并只把其中落后文件所在目录
   交给 SVNmate 更新；没有落后项时不会执行 SVN update。更新完成后仅保留所选
   文件作为本次核验快照。所有后台 SVN 命令均以无窗口方式运行，阶段和结果显示
   在主界面进度区。更新期间“单号 / 资产”页签和结果浏览保持可用，当前阶段会
   写入所选单号、资产及目录的状态列；未选项和已完成项保留原状态。
9. 点击“迁移”后直接复用更新前确认的资产范围，不再重复选择；工具只增量检查
   快照后的源提交和目标状态，再一次调用 UE 迁移、按海外 Jira 准备
   TortoiseSVN 提交窗口。窗口关闭后只读取快照 revision 之后的新提交并统一
   复核，不再重复扫描完整源、目标历史。通过纯“核验”入口生成、尚未选择范围的
   清单仍会在迁移前显示 `/Game/...` 资产目录树。若待处理任务中没有可由 UE
   自动迁移的 `.uasset/.umap`，选择窗口会列明无源提交、人工处理文件或待提交
   文件，不再显示无说明的空列表。
10. “国内 trunk → 海外 trunk → 海外 OB”不会直接跨分支写入海外 OB。工具先
    完成国内 trunk → 海外 trunk，只有第一阶段逐文件复核全部通过后，才继续
    海外 trunk → OSOB；纯海外任务直接执行第二阶段。
11. “国内 trunk → 国内 OB”使用同一 `SERIA-*` 作为源和目标提交证据，执行本地
    工作区精确核验、迁移、提交和复核。未配置可用的国内 OB 工作区时，主动作改为
    “配置国内 OB”；当前不会误用海外远端 SVN 状态。
12. 提交目标文件并全部完成后，原“迁移”按钮会切换为“复核”，用于重新读取提交
    状态。

状态筛选行右侧的固定进度条展示当前阶段及已用时间。流水线结束后，详情区分别列出
快照预检、UE 迁移、目标扫描、等待提交、增量复核和总耗时。checkout 窗口关闭后，
工具增量查询海外 Jira 的 SVN 提交日志并逐文件检查本地状态；提交覆盖路径且没有
遗留本地修改的文件标绿。进度条左侧保留最近一次刷新或复核时间；所有文件完成时
进度条转绿，仍有待处理项时为橙色，执行失败时为红色。

默认固定表（可在设置中分别修改）：

```text
https://bytedance.larkoffice.com/wiki/N7YJwiV4FivSiuko5FCc90O0nEc?sheet=kGEBNH
```

固定表链接可以带旧的 `sheet` 参数；自动入口会按按钮路线在最近 12 个可见页签中
选择第一张含有效任务的页签。单独粘贴、且没有 SERIA 映射的 OSCOA 行按纯海外
Trunk → OB 任务处理，不会误归类为国内 → 海外 Trunk。
标准国内迁移行使用 `OSCOA完整标题&&&&SERIA完整标题`；工具还会识别“纯海外单子”、
“单提OSOB”和“不合并”分段。两个工作簿分别缓存，在线读取失败时使用各自最近一次
成功缓存。

## 更新

MigrationGuard 使用独立的 `migration-guard-latest` 发布通道，版本号见
`migration_guard/VERSION`。SVNmate 的工具模块区域可独立安装、检查和更新，不与
SVNmate 主程序版本绑定。

## 状态

Jira 项目进度根据工单的 `jiraStatus` 和 `jiraVersions` 计算，资产状态根据远端
SVN 中带对应 Jira 单号的提交记录计算：

- **国内 trunk**：国内 Jira 已登记 `trunk`，海外 Jira 尚未登记 trunk。
- **海外 trunk**：海外 Jira 已登记 `trunk`。
- **海外 OB**：海外 Jira 已登记包含 `OSOB` 的版本。
- **状态未知**：任一 Jira 无法读取；不会阻断其他单据。

资产树将国内、海外 trunk 和 OSOB 的同模块相对路径对齐。目录显示“已提交数/资产
总数”，叶子显示最终动作和 revision；目录和资产使用相同的阶段颜色，双击叶子可
复制资产路径。合海外 Trunk 时，到达海外 trunk 即计为完成；合海外 Trunk-OB
时，到达海外 OB 才计为完成。该远端证据无需工作副本，但不包含本地未提交修改，
点击“复核”后才会检查本地状态。
远端查询起点优先取所选 Jira 中最早创建日期前 3 天，并受设置中的最大回溯天数
限制；切换任务、开始本地核验或退出程序会取消旧查询，避免旧结果覆盖当前界面。

- **未迁移**：目标没有本地修改，也没有目标单号提交证据。
- **待提交**：目标存在 modified/added/deleted/replaced 等本地改动。
- **已完成**：目标单号提交已覆盖该路径，且没有遗留本地修改。
- **已提交**：本批次其他目标单号已经提交同一路径，不再重复迁移。
- **源已删除**：该单提交过此路径，但之后的 SVN revision 已删除文件或父目录；
  当前旧单无需迁移该路径，也不会触发 SVN 更新或进入 UE 迁移清单。
- **需更新**：目标工作副本落后于仓库状态。
- **需确认**：删除或提交动作无法自动确认。
- **阻断**：冲突、路径映射或 SVN 命令失败。

批量核验中没有找到源文件提交的单据会显示为紫色“需确认 / 任务”行，并在底部直接
列出单号。这可能表示任务没有 SVN 资产改动，或提交使用了其他 Jira 单号；它不会
与冲突、路径映射失败等真正的“阻断”混在一起。

远端查询和本地复核都提供“单号 / 资产”双视图。单号页签按任务聚合状态并可展开
资产；资产页签对相同路径去重，选中资产或目录后，右侧显示其涉及的全部单号。
每条关联同时显示任务文字描述；一对多映射按原始 Jira 标记切分描述，不混用标题。
路径层级已经在左侧树中完整呈现，右侧不再重复路径。本地复核选中资产叶子后，可用
“定位文件”在资源管理器中选中目标工作副本文件；远端模式没有本地路径，因此
该按钮保持禁用。双击资产叶子可复制目标路径。

批量迁移通过 `127.0.0.1:12031` 连接运行中 UE 的 OmniMcpCore。执行前会校验
当前 UE 工程和 `BranchContentPath`；已完成或已待提交的资源不会重复迁移。表格、
删除项及跨 Jira 共享文件保留为人工处理项，工具不会自动提交或覆盖这些内容。
