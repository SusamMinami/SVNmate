# Kimodo N113 身体重定向测试

> 日期：2026-09-14。实测研究，不是产品能力说明。
>
> 结论：真实 N113 身体驱动及带蒙皮 FBX 往返通过；视觉验收未通过，
> 不可作为可直接导入生产的动作交付。
>
> 同日续测已纠正衣物判断：原角色是披衣，袖管并不包裹手臂，不能强制跟随前臂。
> 已完成独立衣物参考动画和独立脸部预览，详见末尾“同日续测”。

## 范围与来源

用户指定 n113，并要求复用运镜沙盒配置的路径。读取桌面配置中的
`npcAnimationDirectories`，在动作库中定位 `Npc/N113_Ratking`。
使用 Ratking 本体，不使用同编号 Henchman、轮椅和坐姿变体。

- 身体：`SK_N113_Ratking.fbx`，一个骨架、186 根骨骼、10 个 Body/Hair LOD 网格。
- 参考：`A_N113_Ratking_Idlestand1.fbx`，174 根骨骼，动画范围 0–180。
  只核对结构，未将待机动画混入生成结果。
- 差异：参考动画省略 13 个 Nub 末端骨，另有一根身体源文件没有的辅助骨。
  因此不以已有动画文件的骨骼集合覆盖身体源骨架。
- 脸部：`SK_N113_Ratking_Face.fbx` 是 ASCII FBX，当前 Blender FBX 导入器拒绝。
  本轮不转换、不加载脸部，不生成表情。
- 动作：复用上一轮 120 帧、30 FPS 的 SOMA 约束样本，没有进行文本生成。

源文件只读，输出全部位于本机 `%LOCALAPPDATA%/Kimodo`。身体与参考动作
在测试结束后重新计算 SHA-256，与检查前一致。没有 UE 连接、资产导入、
BP/Montage 修改、Excel 写入或产品发布。

## 适配过程

1. 复用固定 Rokoko 副本及 Blender 5 Channelbag / 单次 NLA bake 适配。
   仍不是官方原版插件全功能兼容验证。
2. 建立 22 个主骨骼映射，并追加四个前臂/小腿扭转骨映射。
   非映射骨保留工作参考姿势中的局部关系，继承父骨运动。
3. 对源 SOMA 朝向旋转 180 度，按髋部到踝部高度缩放约 `0.88638`。
   校准工作副本到源参考姿势，不修改原目标骨架的绑定矩阵。
4. 身体 FBX 导入后，网格表现为 Y-up、骨架为 Z-up；仅在测试场景内对
   网格应用 X 轴 90 度转换，供蒙皮检查。此修正只适用于本次文件，
   尚未成为通用 FBX 规则，也未通过 UE 对照确认。
5. 工作骨架先去除父级并归一化对象变换。复制回原骨架时仅复制位置与旋转，
   避免完整变换复制导致根骨产生 100 倍缩放。
6. 最终保留原身体骨架全部 186 个名称、父子关系与局部绑定矩阵，
   在其上烘焙 1–120 帧动画。

手指仍是原参考手型，不是 Kimodo 生成的独立手指表演。扭转骨使用主肢体完整旋转，
没有做按角度分配的专业 twist 解算。头发、披风、袖管没有物理模拟或专项辅助骨解算。

## 往返结果

动画专用 FBX 的尝试暴露出参考姿势和导出骨轴问题，不作为已验收产物。
最终验证 FBX 包含 LOD0 身体/头发蒙皮，使文件带有可验证的绑定姿势。
这不是只含动画的生产交付格式。

使用导出骨轴 X/Y。骨轴重表达会产生原始骨矩阵旋转差异，所以旋转比较使用
`当前世界矩阵 × 世界绑定矩阵的逆`，而非把不同表示下的原始骨轴直接相减。
另行核对全部名称、父子关系和绑定关节位置。

| 项目 | 实测结果 |
| --- | ---: |
| 帧数 / FPS | 120 / 30 |
| 保留骨骼 | 186 |
| 全 120 帧、全骨骼最大世界位置误差 | `0.00003849 m` |
| 全帧、全骨骼绑定相对旋转误差 | `0.00097656 rad` |
| 绑定关节最大位置误差 | `0.00001581 m` |
| 七关键帧 LOD0 蒙皮包围盒最大往返误差 | `0.00000721 m` |
| 右手总轨迹长度 | `2.2023 m` |
| 左 / 右踝距首帧最大位移 | `0.00290 / 0.00387 m` |

踝部位移不是鞋底接触验收；包围盒一致不是逐顶点一致，也不是无穿插证明。
最终 FBX SHA-256：
`ff4239debdfe19d12ab74d21d444003348ab7867c6600432164e9576d96117b0`。

## 视觉结论

从最终 FBX 回读场景渲染正面、侧面共 120 张诊断图；组成 60 帧双视角 GIF，
读回验证总时长 4000 ms。检查了放下、抬手与摆动关键帧。

- n113 原身体网格能随动画运动，没有替换为通用人形模型。
- 补充前臂扭转骨后，手臂撕裂现象改善。
- 首轮曾把袖管与前臂方向不匹配判为错误；同日对照原 Talk 动作后，
  确认角色为披衣设计，手臂不穿袖管。此判断撤回，真正缺少的是独立衣物动画，
  不能强制按前臂跟随，也不能假定原运行时一定会自动修好。
- 未加载独立脸部和原材质贴图，头部空缺不应解读为动作破坏了脸部资产。
- 没有完成肩部、手指、衣物、鞋底、Root Motion 的生产验收。

### 面部实测

复用项目已安装的 Three.js `FBXLoader` 解析 ASCII 源脸，禁止纹理搜索和下载。
Blender 导入器仍不支持此 ASCII 文件，但不再因此阻断本地几何/表情预览。

- 源脸 `SK_N113_Ratking_Face.fbx` 的蒙皮使用独立 `Face01` 骨骼，包含
  62 个 Morph 通道，不是身体 SOMA 骨架的一部分。
- 同名 Talk Body / Face 时长均约 4.5333 秒。但 Talk_Face 只有网格对象
  Transform 动画，没有读到 Morph 动画；Three.js 与 Blender 二进制 FBX
  原始节点解析结果一致。仅文件配对成功不能证明有表情内容。
- `AM_Emotion_Anger_Face` 则有 62 个 Morph 动画轨道、时长约 3.6 秒。
  测试复用这些轨道，剩余 0.4 秒保持末帧；27 个通道实际变化，
  面部局部顶点距首帧最大变化约 `0.01528m`，所有求值顶点为有限值。
- 本地将脸部按厘米转米、Z-up 的源几何挂到身体头骨参考位置，再逐帧跟随头骨。
  检查挂接位置误差为 0，但这只是当前本地规则自身的一致性；
  **未核验 UE Socket、组件相对变换、后处理动画蓝图或头颈接缝。**
- 保留中性脸和复用 Anger 两份 `.blend`；脸部不是 Kimodo 生成，
  表情与挥手的语义匹配也未作制作批准。当前预览不含原材质。

### 真实 Face 挂接

读取 `BP_N113_Ratking` 的 SCS 节点和 `face_GEN_VARIABLE` 模板：

- 父组件：`CharacterMesh0`。
- 挂接骨骼：`Bip001-Head`。
- 相对位置 `(0, 0, 0)`，相对缩放 `(1, 1, 1)`。
- 相对旋转：Pitch `90`、Yaw `0`、Roll `-180` 度。
- Face Mesh：`/Game/Seria/NPC/N113_Ratking/SK_N113_Ratking_Face`。
- Face Skeleton：同目录 `SKEL_N113_Ratking_Face`。
- 模板动画模式为 Animation Blueprint，但 `anim_class=None`。
  此结果不说明运行时没有设置动画类，尚未执行 PIE 或验证曲线消费。

普通 CDO 的组件枚举没有包含 SCS 创建的脸部组件；模板上的
`get_attach_socket_name()` 也返回 None。实际挂点取自 SCS 的
`AttachToName` 和 `ParentComponentOrVariableName`，不可据前两者误判为未挂接。
Python 未暴露 SCS 属性，最终通过已有只读
`reflect.read_object_property` 逐字段读取。

本地按头骨参考位置拼接的预览仅证明本地方法一致，尚未把上述 UE 旋转经
坐标系转换映射到 Blender，因此不宣称脸部朝向、接缝与游戏完全一致。

### 身体目标差异

实际 Body Mesh 为 `body/SK_N113_Ratking`，Skeleton 为
`body/SKEL_N113_Ratking`；动画蓝图为 `ABP_N113_Ratking`，
Body 的 Post Process Anim Blueprint 为空。

UE 组件读出 189 根骨骼，源 FBX 是 186 根。将源骨名中的空格替换为连字符后：

- 源 186 个名称在 UE 中全部存在，无额外源骨。
- UE 多出 `Root`、其子骨 `Bip001`、右手下的 `N113_Ratking222_Bone123`。
- 公共骨父级仅骨盆不同：源骨盆无父骨，UE 为 `Bip001-Pelvis -> Bip001 -> Root`。
- 这里只对比名称和层级，尚未证明两者绑定变换完全相同；
  原 186 骨 FBX 往返通过不能等同于可直接导入现有 189 骨 Skeleton。

原始只读响应保存于本机 `20260914-n113-body-face-verified/` 中的
`ue-component-probe.json`、`ue-details-probe.json`、`ue-attachment-probe.json`
和 `ue-scs-probe.json`。编辑器保持开启供后续核验。
下一步以实际 UE 目标骨架和 Face 挂接规则完善适配；写入测试仍需明确范围。
