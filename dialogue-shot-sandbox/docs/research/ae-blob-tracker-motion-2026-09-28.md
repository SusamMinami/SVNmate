## 结论与适用边界

AE Blob Tracker 最值得借鉴的是“对象被捕获、被关联、被处理”的视觉语言。
角框、中心点、轮廓、稀疏连线与局部填充，可以为镜头沙盘的长任务提供辨识度，
同时解释正在处理什么。建议先建立少量可复用动效，再按任务语义组合，
无需先引入图像检测或复杂着色器。

上游 README 明确声明源码不公开，插件面向 After Effects 2025/2026。
其说明允许个人和商业使用，并允许署名后原样分发插件二进制；
这不等于开放了实现源码，也不能据此把演示素材当作产品资源。
因此当前路径是参考公开行为，独立实现 Electron/React 适用的效果。<a href="#source-1">[cite:1]</a>

上游算法、确定性、MFR 安全与精度描述均属于作者单一来源声明。
本次抽帧能观察到角框、标记、连线与局部色块，不能证明其跟踪算法质量，
也不能证明相同效果在沙盒与 UE、端侧推理并行时的性能。

## 上游效果的组成与迁移价值

用户指南将系统分为 Detection、Blob Boxes、Center Markers、Labels、
Connection Lines、Region FX、Compositing、Animation、HUD Extras。
这是一套参数化的对象覆盖层，而非单一加载动画。<a href="#source-2">[cite:2]</a>

| 效果 | 上游公开行为 | 沙盒中的建议用法 |
| --- | --- | --- |
| Brackets / Crop Marks | 在检测对象边界绘制角框 | 圈定当前扫描对象、待写入区域或已返回结果 |
| Contour / Convex Hull | 轮廓线与凸包；可平滑轮廓 | 启动标志或紧凑等待图形的描边；首版用预制 SVG 路径 |
| Center Markers | 点、加号、十字、圆环 | 标记真实角色槽位、当前任务节点，减少文字堆叠 |
| Marching Ants | 虚线相位沿边界移动 | 紧凑的不定进度指示，不表示完成百分比 |
| Scan Sweep | 水平或垂直扫过画面 | 仅在任务小区域运行；不扫过整张字幕表和镜头画面 |
| Sequential / Star / MST | 顺序、星形与最小生成树连线 | 表达已有处理顺序或对象关系；没有业务边时不伪造依赖 |
| Delaunay / Voronoi | 三角网与空间分区 | 低优先级；更适合独立品牌图形或未来空间诊断，不适合作为默认写入等待 |
| Birth Pop | 新跟踪 ID 出现时单帧缩放与透明度变化 | 转译为新结果的短促显现；不照搬单帧闪现，不对缓存恢复重播 |
| Hatch / Cross-Hatch | 区域内斜线填充 | 给待处理图形增加轻微材质感，避开正文和输入框 |
| Glitch / Time Shift / Label Flicker | 局部像素扰动、历史帧与标签随机隐藏 | 首版不采用；会干扰精确数值，也容易把正常等待表现为故障 |

上表的上游行为依据用户指南；右栏均为本项目设计建议。<a href="#source-2">[cite:2]</a>

## 建议接入位置与优先级

| 顺序 | 位置与触发 | 建议画面 | 当前数据能力 / 需要补充 |
| --- | --- | --- | --- |
| 第一批 | 动画语音底栏：检查差异、确认写入 | 角框圈定状态位，短线沿框运行，成功后收束为结果图标 | 已有 `review/apply`；没有服务器内部逐项写入进度 |
| 第一批 | 语音对齐 / ASR 状态行 | 中性轮廓持续描绘，真实阶段变化时短暂聚拢；完成即停止 | 已有 job ID、state、stage；没有逐句进度 |
| 第一批 | 动画目录：读取、全量扫描、单项重读 | 当前处理图标描边，进度细线推进，返回行轻量显现 | 已有 `done/total` 和逐项结果；显式暴露当前处理路径会更可靠 |
| 第二批 | TRAE / Mira / 端侧顾问等待区域 | 小型“节点捕获—稀疏连线”图形，任务状态保留在旁边 | 已有等待与阶段信息；真实节点标记要按各导演的数据粒度接入 |
| 第二批 | 分镜导出弹窗底栏 | 与动画写入共用状态图形，根据实际流程显示检查或写入 | 已有 busyLabel；“写入—回读—保存”细分需服务端事件支持 |
| 第二批 | NPC 迁移及动作增补的当前步骤 | 源到目标的短路径运行，返回结果后出现完成标记 | 已有业务步骤与最终清单；逐文件移动必须等进度接口 |
| 第二批 | 显式读取 BP 站位 / 场景快照之后 | 对真实角色或对象短暂显示角框、中心点，再回到稳定视图 | 可用已有几何信息计算投影；不代表检测到真实角色轮廓 |
| 第三批 | 启动与首次加载工作区 | 产品标志或取景框轮廓一次成形 | 先处理现有启动跳过、减动与退出计时一致性 |
| 第三批 | 端侧模型安装 | 安装图标局部运行，真实阶段切换时归位 | 语音安装已有阶段，没有下载字节进度；不能显示虚构百分比 |

第一批兼顾表达力和接入成本。最有观看价值的是语音长任务，
最有实际解释价值的是写入状态，最容易获得真实进度的是目录扫描。
第一批也能验证同一语言在小按钮、行内状态与列表三个尺度上的一致性。

### 方案一：角框捕获与归位

一次请求开始时，四角在现有状态位附近短促靠拢；等待时只有边线相位移动。
真实结果返回后，角框停止，合成静态结果符号。视觉状态始终围绕同一个位置，
不扩大底栏、不把按钮变成新面板、不移动其余控件。

检查通过表示“可确认写入”，不能演成“已写入成功”。
LevelSequence 成功必须仍然显示“已写入，UE 未保存”或服务返回的对应说明；
分镜导出和 Excel 的保存规则不能套用该文案。
连接超时且结果不确定时，动效停止并进入“待核对”，不自动重试，也不武断宣称零写入。

### 方案二：语音轮廓等待

在现有任务状态行内，用紧凑的波形风格线条或取景框形状承载描边运动。
如果使用波形风格，它只能是装饰性的任务符号；当前接口没有振幅数据，
不能伪装成真实声波或逐句识别位置。真实波形需要另做音频采样与缓存。

模型运行时，字幕和时间输入保持固定。结果到达后即显示全部真实建议，
不按虚构的识别顺序慢慢解锁台词。
点击“采用到待写入”时，时间字段即时更新；同一行只播放一次轻量角框收束，
帮助用户看见“建议已进入草稿”，不会重新新增一份台词列表。

### 方案三：导演等待的关系图形

在现有等待区域内，把一个取景框与少量点、短连线组合成循环图形。
抽象图形不附带假 ID、假评分或假坐标。若使用真实角色槽位，
则只显示当前已知角色；只有已有业务关系才能绘制带业务含义的连接。

TRAE 仍在排队时，画面应保持“等待接收”，不能表现成已开始逐镜评分。
不覆盖中央取景画面，不把平滑动画反馈到相机位置、焦距、ShotPlan 或真实时间轴。
用户继续浏览旧方案时，图形留在任务区域，不追随切镜重播。

## 实现上可以借鉴什么

### 分离对象、样式、时间与任务状态

上游将检测、覆盖层与动画参数分组；沙盒可借鉴这种分层，
但直接从 DOM 边界、任务对象或 Three.js 已知几何取得目标，
无需对自己的界面截图再做颜色阈值和轮廓检测。<a href="#source-2">[cite:2]</a>

建议形成三个层次：

```text
业务 hook / 真实任务事件
        ↓
任务状态适配：ID、阶段、计数、结果、可取消性
        ↓
动效视图：角框 / 描边 / 连线 / 结果归位
```

业务成功由请求和回读结果决定，不由 `animationend`、定时器或描边完成决定。
动效组件不访问 UE、不启动模型、不控制保存，也不因重新挂载重发请求。
已有业务 hook 可以保留，增加适配层即可，不必先重构统一任务调度器。

### 稳定身份比随机抖动更重要

上游通过稳定 ID 支持平滑与新对象显现；沙盒可以用 assetPath、sectionPath、
字幕 row key、shot ID 和 job ID 实现相同的视觉连续性。<a href="#source-2">[cite:2]</a>

一次任务增加独立运行代次，旧完成事件不能让新任务停止播放。
缓存恢复、切换工作区和滚动回可见区域不算“新结果”，不触发成功演出。
进度数值即时准确；仅对图形显示做短过渡，不平滑或延迟真实状态。

### 用确定性时间表达节奏

上游声明同一帧产生相同图像，动画依据合成时间运行。<a href="#source-1">[cite:1]</a>
沙盒可以借鉴为可复现的局部时间轴：同一 preset、对象与采样时点得到相同形态。
如确需变化，使用稳定 seed；不要每次 React render 调用随机数改写位置。

测试可以直接停在捕获中段、运行中段和完成状态，比较连续切换和打断后的图形。
这种可复现性比大量不可控粒子更有维护价值。

### 首版选择 CSS、SVG 与已有 WAAPI

角框用少量 DOM/SVG 元素；平移与透明度尽量采用 CSS；
路径描绘用 SVG stroke；中断、重定向与阶段衔接复用 Web Animations API。
WAAPI 提供播放、暂停、反向、取消等控制，不要求额外安装动画库。<a href="#source-3">[cite:3]</a>

`transform` 与 `opacity` 通常更利于合成；SVG 描边、裁切、滤镜和 Canvas
并不因为使用 WAAPI 就自动成为“免费 GPU 动效”。
需要限制绘制区域、测量绘制成本，`will-change` 只在必要期间启用。<a href="#source-4">[cite:4]</a>

当前项目已用 React、Three.js 和 WAAPI；不建议为首版增加 OpenCV、AE 宿主、
独立 WebGL 上下文、实时像素回读或整套 Motion/GSAP 依赖。
这些方案不是永久排除，而是目前三个首批效果均不需要。

## 节奏、密度与运行规则

以下为原型调参起点，尚未实测：

| 项目 | 建议 |
| --- | --- |
| 即时响应 | 点击后立刻展示 busy、禁用重复提交并保留任务文字 |
| 较丰富等待图形 | 请求持续约 250ms 后再显示，短请求不闪一下大动效 |
| 捕获 / 结果收束 | 约 160–240ms；真实结果与操作可用性不等待动画结束 |
| 等待循环 | 约 1.2–1.8 秒一个轻量周期，仅真实 pending/running 期间运行 |
| 动态焦点 | 每个可见工作区最多一个主要等待图形，其余用紧凑状态 |
| 规模 | 首版关系图控制为少量节点；不为数千目录行创建独立循环 |
| 色彩 | 黑白为主体，空间关系用既有青色；黄色仍归主操作，不铺满扫描区域 |
| 减少动态效果 | 去掉扫动与空间位移，保留静态角框、阶段文字和真实计数 |
| 隐藏 / 最小化 | 暂停图形与非必要帧循环；恢复直接展示当前状态，不补播过期成功 |

不使用慢速揭示隐藏结果，也不引入最短任务等待时间。
键盘触发保持即时操作，装饰入场可以省略，异步运行状态仍须可见。
装饰层不接收指针，不夺焦点，状态播报只随阶段变化而非每帧更新。

扫描的 `done` 当前包含成功和失败的已尝试项，因此进度表达“已处理”，
不能直接称为“已成功缓存”。目录和字幕结果列表均不自动滚动追逐当前任务。

## 对现有技能与项目文档的补充方式

Emil 提供频率、响应速度、连续性和缓动判断；Impeccable 提供视觉方向、
语义、预算和验收要求。AE Blob Tracker 提供的是具体的视觉词汇和可组合方式。
三个来源互补，不能靠再增加泛化口号自动得到有特点的成品。

下一步更有价值的交付是一个小型本地动效样例集与可复用组件，
每个样例均含运行、成功、失败、取消、结果不确定与减少动态效果状态。
先在动画语音工作区验证，再收敛：

- 项目专用视觉与状态规则进入 DESIGN 的任务动效章节。
- 数值、缓动与图形 preset 归入一个实现入口，避免组件间复制。
- 真实阶段由各业务 hook 提供；不在通用样式中推测任务流程。
- 仅当多个项目都复用同一方法时，再考虑封装专门 skill。

本次不修改上游技能，不覆盖既有导航动效，不把研究建议写成现行规范。

## 后续实施的验收边界

验证正常完成、瞬时完成、失败、取消、重试、快速重复触发与晚到结果。
验证完整写入、部分成功和连接中断，不用统一成功图形掩盖各流程的差异。
用接口拦截验证表现，不为动效验收执行正式资产写入或下载模型。

在实际 Electron 中检查常用桌面尺寸与 100% / 150% / 200% 系统缩放，
尤其是细角框清晰度、文本对比度和按钮尺寸。
在 Three.js 预览与代表性并行负载下采样主线程、绘制与图层，
确认任务停止或窗口隐藏后不遗留 RAF、动画对象和无用连续渲染。
单张截图不能证明中断连续性与运行流畅度。

本次实际完成：公开资料阅读、官方 GIF 抽帧观察、源码与历史研究对照、
既有截图复核、研究文档与导航更新。
