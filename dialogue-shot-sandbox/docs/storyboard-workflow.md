# 分镜工作流与协作

> 状态：现行行为规范。维护加载、方案切换和 AI 任务状态；不重复 UE 字段协议。
> 站位身份见 [BP 集成](ue-formation-integration.md)，写入见
> [分镜导出](dialogue-camera-export-design.md)，窗口布局见 [DESIGN.md](../DESIGN.md)。

## 加载与搜索

1. 输入四位对话 ID 只从本地配置加载对白，不连接 UE，不启动规则导演、VLM、
   TRAE 或 Mira。设置目录完成后也不自动读取首个对话。
2. 点击搜索栏下方“读取 BP 站位”才读取 Formation 和 UE 已有镜头。工作台区分
   纯文字/未设计、UE 已有镜头、导演生成，不能把只读结果标为导演生成。
3. BP 缺失、身份映射失败或 UE 离线不阻断对白；在显式 UE 读取中，BP 不可用
   也不阻断独立的对话资产镜头回读。缺坐标基准时可按 UE 原点预览并警告。
4. 未生成分镜时仍能点击对白行选择节点、进入导演/镜头/音频/UE 页签。导演与
   镜头显示空状态；音频与动作可按节点编辑和导出。导演入口只在主动点击后选中。
5. 全文搜索忽略富文本标签、空白、标点和全半角差异；桌面实时数据首次未命中
   时重读当前配置 CSV 后再判断。搜索结果编辑不依赖分镜。
6. 批量替换只写明确勾选节点，保留原文校验、脏资产检查、回读、按资产保存和
   失败恢复。不能将“全部命中”视为用户已确认范围。

## BP 与占位选择

- 生成前确认沿用 BP 或导演自主占位。BP 方案默认只允许调整 0 号玩家；
  勾选“固定 0 号玩家位置”后所有 BP 槽保持原始位置和朝向。
- BP 定义场内数字槽集合，0 号玩家和未发言角色不能因无台词而丢弃。
  角色身份、超过 12 槽的取舍和缺失模型审核按 BP 集成规范处理。
- 占位对比中的 BP 预览不叠加首镜 `facingOverrides`：锁定玩家时显示全部原值，
  未锁定只显示 0 号玩家调整；首次弹窗允许关闭，不强制采用。
- 左栏只显示 BP 资产名，不铺完整 `/Game/` 路径。当前采用 BP 时点击资产名
  可重新读取，确认前保留当前方案。
- BP、规则和已完成 AI 方案保留可切换预览；普通切换不重读 UE 或重新调用 AI，
  保留当前镜头编号，仅在目标方案较短时收敛到最后一镜。
- BP 被跳过/失败后的 fallback 原因应保留，后续 `applySequence` 或规则分析
  不得覆盖为“读取成功”。

## 导演与验收

| 模式 | 责任与降级 |
| --- | --- |
| 规则导演 | 几何系统生成合法候选，可选端侧顾问分析节拍并逐镜评分；不可用时保留基线 |
| TRAE 协作 | 本地队列提交 `shot-plan.v5`，由已登录 TRAE 领取、续期、回传 |
| Mira AI | 本地桥通过 `lark-cli` 发送请求并轮询；无授权、非法响应等显示降级原因 |

- 端侧顾问仅按请求启动，不随应用启动；模型不得输出摄影机坐标。最多三个
  合法候选/镜，按镜头与候选顺序全量逐图评分，不恢复“四镜抽样”。
- 左侧显示候选生成与评分进度，检查器展示分数、排名、实际采用项与理由。
  模型具体配置、租约和协议归 [端侧顾问](rule-director-edge-advisor.md)。
- 所有生成方案经过 Schema、关系轴和投影验收。只对失败镜头定向返修一次；
  仍失败的镜头保留并标红，不中断整组。
- `projection.issues` 只有 error 判失败；warning 是建议，info 是说明。
  30°规则仅用于同主体且景别变化不足的切镜建议，不作为全局红色错误。
- 静态关系覆盖可以延续，不跨进出场边界合并；群像观察现有朝向，不把所有角色
  自动转向中心。摄影与体型规则归 [镜头语言](shot-language-rulebook.md)。
- 场景参考是只读 AABB 快照，不等于真实网格/深度验收；独立空镜未校准前不导出。
  场景数据外发须单独授权，参见 [场景接入](scene-composition-integration.md)。

## TRAE 任务状态

1. 当前对话 ID 未变化时复用对白和已读 BP。进入 TRAE 后先确认占位策略和玩家
   锁定设置，再检查本地缓存与共享库；无精确命中才创建任务。
2. 已在 TRAE 模式时再次点击属于显式重新生成：仍先确认策略，再绕过缓存与
   同内容活动任务。完成后直接应用对应方案，不为修正 BP 占位再发第二轮。
3. 排队或生成时可切回规则方案，不能因此取消或丢弃后台结果。
4. 协作弹层列出具体任务；拖拽顺序持久化并决定 MCP 领取次序。删除仅限未领取
   任务，中断处理任务是另一操作，均先确认且由服务端校验状态。
5. TRAE 处理期间持续续期心跳；租约失效后服务端取消任务并通知工作台。界面等待
   超时仅结束等待，不等同于任务取消，晚到结果仍可复用。
6. 提供“中断分析”。生成期间重新读取 BP 时，先确认并中断任务，再刷新位置；
   保留已显示分镜与占位。

## 缓存、共享与反馈

- 指纹包含对白、角色、上下文、约束、占位策略与版本；精确命中可恢复，
  相同活动任务可复用。输入变化使旧命中失效。
- 分镜内存缓存按最近使用顺序最多保留 6 组；当前分镜和未导出的编辑草稿不能
  被淘汰。它与持久任务结果缓存不是同一层。
- TRAE 本地未命中时查询飞书共享库；精确共享命中不再次生成。不同方案需
  本地/共享比较并由用户决定是否覆盖远端，飞书不可用只跳过共享步骤。
- 返修案例按失败镜头记录首轮/返修决策和验收。只有已审核且通过或改善的案例
  可用于后续提示，不复制旧坐标；关闭案例收集后不读写。
- 导演偏好是采用、拒绝、修改等审美选择，与技术返修库分开。使用类型化契约和
  稳定 fingerprint 更新，不能产生互相冲突的重复样本。
- 接入目录、端口与离线环境变量见 [开发与联调](development.md)。
