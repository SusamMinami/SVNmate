# UE 节点创建与自动连线支持建议

> 状态：接口建议，非已部署能力。统一请求信封见
> [资产 Patch 需求](ue-editor-asset-patch-api-requirements.md)；
> 原型与探测进展见 [插件可行性](local-dialog-plugin-feasibility.md)。

## 当前边界

当前沙盒具备读取 UE 选择、读写已有节点属性、修改 Blueprint 组件、
预检/确认/回读/保存的链路，但没有接入“创建图节点和连接引脚”的业务接口。
正式 UE 项目的插件源码不在本仓库；`tools/local-dialogue-probe` 是独立原型，
不等于已部署接口。不能据此断言其他 OmniMcpCore 版本也没有图编辑能力，
需以目标编辑器的工具清单或接口声明确认。

需区分三种对象：

- Formation Blueprint 的组件树：现有 `bp.add_component` 修改的是 SCS
  组件，不是 Event Graph 中的节点。
- 普通 Blueprint Event Graph/Function Graph：通常是 K2 节点与类型化引脚。
- 本工具的对话图：当前读取的是 `SeriaEdDialogGraphNode`、
  `DialogGraphNodeData`、`CommonDialogGraphProperties`。它是项目定制的
  DialogGraph，创建和保存必须遵循 SeriaDialogEditor 自己的规则。

建议先支持当前工作流的对话图；普通 K2 图可作为独立能力后续接入。

## UE 侧最小能力

建议在 Editor-only 模块中扩展现有 `SeriaDialogEditorSubsystem`，
或提供专用的图编辑服务。对外暴露受控 UFUNCTION，供现有
`script.eval_python_expression`/反射桥调用，或注册为 OmniMcpCore 工具。
一般不需要另开端口，也不需要重写沙盒 TCP 通信。

下表名称均为**建议接口**，不是已确认存在的 UE API：

| 建议能力 | 输入/输出重点 |
| --- | --- |
| `get_graph_capabilities` | 协议版本、支持的 graph kind、节点类型、字段、引脚、插入/连线策略、撤销和保存支持 |
| `get_graph_snapshot` | 资产路径、Graph GUID、修订指纹、脏状态、节点 GUID/业务 ID/类型/位置/字段、引脚标识与连线 |
| `preview_graph_edit` | 接收创建/插入/连线计划；检查权限、节点 ID、引脚兼容性、需断开的旧连接；返回差异和审核令牌；不修改资产 |
| `apply_graph_edit` | 校验审核令牌和最新修订；以一个编辑器事务执行整个计划；返回真实创建的 GUID/ID、连线、校验与保存状态 |
| `get_graph_edit_result` | 按 requestId 查询已执行/失败/处理中结果；网络超时后不盲目重放写操作 |

没有引脚概念的自定义图，可返回项目定义的输入/输出端口或边，但必须有稳定标识。
节点显示标题和反射返回的 UObject 临时别名都不能作为长期身份。

### 节点创建

应复用“编辑器右键创建节点”所用的 Schema Action/节点工厂路径，保证：

1. 正确的 Graph/Outer、事务标记、节点 GUID、默认引脚和节点初始化。
2. 对话专有 `DialogGraphNodeData`、类型和属性别名完整建立。
3. 对话业务 ID 唯一，明确 `00` 配置节点、Start/End、分支和普通对白的规则。
4. 必需字段和默认配置由 UE 服务负责，不让沙盒猜测反射结构。
5. 编辑器通知、图刷新和运行数据重建与手动创建保持一致。

对于普通 K2 图，需要额外提供函数/变量/节点类白名单，以及该节点类型的
重建和引脚分配流程。不能简单地 `NewObject` 后塞入 `Graph.Nodes`，
也不能认为所有节点都适合一套通用构造参数。

### 自动连线

普通 UEdGraph 应使用对应 Schema 的 `CanCreateConnection` 和
`TryCreateConnection` 路径；项目对话图则复用自己的连线服务。

- 校验方向、类型、单/多连接限制、通配符和循环等规则。
- Schema 可能要求断开现有连接或创建类型转换节点；这些变化必须出现在预检
  差异中，不能隐式覆盖。
- 默认只新增，不替换旧边；“在 A 与 B 之间插入 X”必须明确展示
  `A -> B` 变为 `A -> X -> B`。
- 自定义对话的 `NextID`、分支/选项出口和运行数据应由同一 UE 业务流程更新。
  只改可见引脚或只改 `NextID`，都不能保证编辑器图和实际执行一致。
- 导出的 CSV 是读取来源，不是图编辑的写入目标。

### 可靠性要求

- 所有 UObject/Graph 修改在编辑器 Game Thread 安全阶段执行。UE 侧负责
  保存、自动保存、GC、资产重载、编译、PIE 等忙状态判断，并返回可识别的
  `EDITOR_BUSY` 等结果。
- 忙状态判断应早于危险的对象查找/反射调用。仅“切到主线程”或“沙盒停止
  定时器”不足以保证保存期间安全。
- 预检和应用都重新检查图修订；用户手动编辑后旧计划必须失效。
- 一个批次对应一次 `FScopedTransaction`/项目等效事务；修改前对相关对象
  `Modify()`，确保成功操作可以一次撤销。
- **事务取消不等于自动回滚。** 失败要由插件明确恢复新增节点、旧边和字段，
  或走经过验证的撤销流程；回读确认恢复结果。不得只调用 Cancel 就报告“已恢复”。
- Graph 通知、K2 的结构修改标记/编译或自定义对话的重建/校验分别按资产类型
  执行，不对所有 DialogGraph 盲目调用 `compile_blueprint`。
- 首版结构写入拒绝已有脏资产；不要为回滚直接重载用户正在编辑且有未保存数据的资产。
- 与统一 Patch 方案一致，应用并校验成功后只标脏，不自动保存。后续保存须单独确认，
  单独报告 `applied`、`validated`、`saved`、`rolledBack`，不把“已应用”视为“已保存”。
- requestId 应幂等；连接中断或超时后查询结果，再决定下一步，禁止重复创建。
- 返回有限的结构化摘要和错误，不记录整图属性/对白正文到高频日志。

保存期间的反射查找需要 UE 侧忙状态保护；沙盒减频和按需读取不能替代它。
连接被重置或端口消失后停止后续写探针，先检查编辑器与日志。

## 沙盒侧怎么接

第一版可复用当前小窗/对话流程，无需新增通用蓝图编辑器：

1. 从 UE 当前选择取得资产、Graph 和节点 GUID，读取能力与最新图快照。
2. 提供“在当前节点后插入”“批量创建对白节点”“按已确认顺序连线”。
3. 本地生成计划，用临时 key 描述新节点之间的关系；业务 ID 由 UE
   校验/分配，不能让 UI 的序号充当真实节点 ID。
4. 服务端请求 UE 预检，在现有确认流程展示新增节点、字段、旧边变化和风险。
5. 用户确认后一次提交，写后回读，并只刷新受影响的节点和对话。
6. 应用期间冻结相关图编辑入口与该图自动回读；外部 UE 保存仍由 UE 侧保护。
7. 返回忙状态时保留计划，修订变化时重新预检，超时时查询 requestId。

建议的代码归属：

- `src/types.ts`：能力、快照、编辑计划、预检和结果类型。
- `src/ue/client.ts`：前端接口。
- `src/app/useDialogueGraphEditor.ts`：独立交互状态，避免继续扩张 App。
- `server/ue/dialogueGraphEditing.ts`：校验、预检和应用的业务服务。
- `server/ue/services.ts`、`routes.ts`：服务门面和 HTTP 适配。
- `server/ue/transport.ts`：继续只处理协议，不加入节点业务规则。

建议 HTTP 路由为 `/api/ue/dialogue/graph/{capabilities,snapshot,preview,apply,result}`；
这些同样是设计建议，当前没有实现。

## 交给 UE 同事的验收场景

- 新建单个普通对白节点，字段、ID、引脚、位置、数据对象完整。
- 在已有 A/B 之间插入节点，仅修改用户确认的旧边。
- 批量创建并连线，重复 requestId 不产生重复节点。
- 不兼容引脚、非法 ID、分支歧义必须拒绝且不改变图。
- 中途失败能恢复原图，成功后 Undo/Redo 与手动编辑一致。
- 保存/自动保存/GC 期间返回忙状态，不崩溃、不做危险反射查找。
- 预检后手动改图，再应用时拒绝旧审核令牌。
- 保存失败与网络断开能查明实际结果，不盲目重复写入。
- 保存并重新打开编辑器后，节点、连线、运行顺序和导出的配置仍一致。

在 UE 没有这些接口前，可以先实现沙盒侧的计划生成、差异预览和协议模拟测试，
但不能宣称能可靠地自动创建/连接真实节点。不建议用鼠标坐标、剪贴板文本粘贴、
直接改 `.uasset` 或绕过 Schema 的反射数组写入作为正式方案。
