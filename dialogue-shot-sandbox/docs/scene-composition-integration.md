# 场景参考与空镜接入方案

日期：2026-09-06。

状态：角色体型与预警改造已实现；本文场景采集、深度验收和独立空镜为后续设计，
尚未接入生产链路。当前本机 UE MCP 12031 端口未连接，不能声称已做引擎实测。

## 结论

推荐混合方案：**地图与落点锚定 + 附近几何清单 + 候选机位 RGB 图 + 按需深度验收**。
不建议只靠一张截图猜空间，也不建议第一版搬运整张关卡到 Three.js。
UE 保留真实场景、材质、灯光与最终渲染；沙盘维护轻量场景代理和可寻址目标，
导演负责叙事选择，确定性几何与 UE 回读负责约束。

## 项目现有基础

- `server/ueBridge.ts::readDialogueSpatialContext` 已解析开始节点的
  `PreviewLevel`、`CommonDialogGraphProperties.PlayerInitPosition`、
  `PlayerForward` 及普通/特殊 `Virtual` 配置。
- `src/data/missionTargetBlueprintSync.ts` 已有
  `worldTransformFromBlueprint` / `blueprintTransformFromWorld`，当前以 yaw
  旋转处理世界与对话局部坐标转换，不应把它当成任意旋转/缩放的完整矩阵实现。
- `server/ueBridge.ts::readSelectedLevelActors` 相关链路已经识别 Actor 的
  Blueprint、Static Mesh、Skeletal Mesh 及 SceneObject 的实际子预览类。
- `buildStoryboardCameraMove` 把沙盘相机转换成 BP 局部厘米，写入
  `PushCameraArg`，`bRelative=true`。它不是直接向世界坐标写一个相机 Actor。
- 当前分镜导出要求每镜至少一个 dialogueId；预览时长没有独立写入空白等待节点。
  因此“在列表插入一张空镜卡”并不等于引擎中能够按时播放。

## 先统一坐标和场景状态

同一个 BP 可以在不同地图、不同位置使用。资产路径只能确认模板身份，不能唯一
确定世界落点。必须为每次场景参考保存 `sceneContext`：

- 地图资产路径、当前已加载关卡/子关卡、实例身份。
- 对话根变换、来源（已确认的场内实例或对话元数据）、是否已人工确认。
- 世界单位（UE cm）及世界坐标到沙盘坐标的显式变换。
- 对话节点/采样时间、任务或流送状态、采集范围、采集时间与内容指纹。
- 完整度标记：已加载范围、漏掉的资产类型、不可读取对象、是否含真实人物姿态。

来源优先级：

1. 用户选中的、类路径吻合的 Formation BP 实例，读取实例世界变换。
2. 已核验的对话地图与 PlayerInitPosition/PlayerForward。
3. 任务目标物匹配出的唯一锚点，展示推断证据后确认。
4. 多实例或元数据冲突时请用户选择，不能静默取最近对象。

`Virtual` 未启用、位置来源是动态玩家或位置属性并未显式配置时，保存的
预览坐标不一定是运行时落点。必须绑定实际实例/运行时上下文或要求确认，
不能把默认零坐标当作真实世界锚点。

沙盘空间中的点先撤销水平居中，再逆转轴映射与米/厘米转换，得到 BP 局部点；
随后应用对话根完整变换得到世界点。Mesh 局部关键点还需先经组件附件链与角色槽位
变换。任何一步都不能重复应用槽位 Scale，不能把 Actor 胶囊中心当脚底。

相机、场景目标、角色和深度必须使用同一坐标基准。地图切换、根位姿变化或模型
移动后，旧场景快照不得作为精确验收依据，需重新采集或明确降级。
不能因缺少 PreviewLevel 阻断普通 BP 注册；场景参考应是独立、可跳过的能力。

## 各种输入的用途

| 输入 | 擅长 | 不足 | 建议 |
| --- | --- | --- | --- |
| 用户截图 | 语义、灯光、色彩、背景杂乱、门窗位置 | 无绝对尺度和相机位姿，单视图遮挡不可恢复 | 作为低可信视觉参考，不能宣称几何通过 |
| 带相机标定的 UE RGB 图 | 实际候选构图、轮廓、背景和材质 | 不能单独计算可靠空间距离；受曝光与后处理影响 | 第一版重点，附 FOV/画幅/位姿和采集节点 |
| 附近模型/组件清单 | 大小、位置、背景目标、空间关系 | Actor 名称不等于语义，包围盒过于保守 | 第一版重点，按需简化 mesh 或 UE 射线确认 |
| 线性深度图 | 主体遮挡、空间层次、穿墙候选排除 | 不提供故事意义，透明物与单视图背面信息有限 | 第二版按候选机位采集 |
| 对象 ID 图 | 识别某像素属于哪个目标，统计可见比例 | 需要额外渲染/标记，不能永久改场景材质或 stencil | 重要目标按需启用 |
| 全量关卡 mesh 导入 | 本地自由预览和射线 | 数据量、LOD、材质、植被、地形和版本维护成本高 | 不作为第一版前置条件 |

### 附近内容怎么查

先确认正确地图及需要的流送子关卡已经加载，然后枚举场内 Primitive Components，
不能仅按资产注册表查询“用了哪些模型”：资产注册表没有每个实例的世界位置。

初始采集半径可从人物群中心 15-30 米开始，随后按候选相机位置、运动扫掠体和视锥
扩大范围。长焦背景、远处地标与离人物较远的相机可能超出初始球体，必须做二次查询。
用组件 bounds 与采集体相交筛选，而不是只比较 Actor 原点距离。

至少分别处理：

- StaticMeshComponent 的 mesh 路径、组件变换、局部 bounds、可见/碰撞状态。
- ISM/HISM 的逐实例变换与索引；不能把整个植被管理 Actor 当成一棵树。
- Landscape、BSP、SplineMesh、动态 Skeletal Mesh、ChildActor、SceneObject。
- 当前不可见/编辑器专用组件、LOD/HLOD 和未加载流送内容的完整度。

清单保留 Actor/组件/实例 ID，用白名单场景标签或人工确认生成“门口”“窗边”
“桌上道具”等目标；不能仅靠 `SM_123` 的名字宣称识别了某个故事物件。
包围盒只做候选粗筛：门框的整盒包含可穿过的门洞，不能把整盒命中直接判为穿墙。
优先让 UE 对少量候选执行可配置的可见性射线/扫掠；无碰撞物件需要渲染深度补充。

### 截图怎么用

每场先取少量概览（俯视和关键方向），让导演理解环境。再只为通过基础几何筛选的
候选机位采集起点/中点/终点 RGB 图，避免为所有组合做高成本渲染。

图片必须附相机世界变换、水平/垂直 FOV 定义、宽高比、实际裁切、节点/采样时间，
并与沙盘的 35mm film gauge 和 UE FOV 转换核对。截图不能包含选中描边和操纵轴。
使用 SceneCapture2D 比截取用户当前编辑器视口更可控，但曝光、后处理、LOD、
Temporal AA 等可能与玩家相机不同，应标注并做同机位对照。

当前 `shot-plan.v5` 的输入是 JSON 文本。不能只往 prompt 塞一个磁盘图片路径，
就认定模型看到了图片。需为支持视觉的 provider/MCP 增加实际图像内容或受控资源
读取能力；不支持视觉时只发送结构化空间摘要，图片仍供人工验收。
截图默认留在本地，外发模型或共享库前必须有明确范围与授权。

### 深度怎么用

使用与 RGB 同机位、同分辨率、同一场景状态的 SceneCapture 输出。
保存浮点线性深度和单位定义，不要把供显示的 8-bit 灰度 PNG 当作厘米值。
区分沿光轴深度与射线距离；若读取的是 device depth，必须用投影参数反解。

对角色眼睛、脸部、肩部、叙事手势等采样点，比较其相机空间深度与对应屏幕区域
深度，识别前方遮挡；对薄遮挡、边缘及透明材质设不确定区，避免单像素判死刑。
运动镜头要采样中间路径，不能只验首尾两帧。
对象 ID 可辅助区分人物自身表面与前景遮挡。

## 空镜协议的实施边界

建议后续升级为带可辨识镜头类型的协议，而不是把环境伪装成人物：

- `dialogue`：保持现有 dialogueIds 覆盖顺序。
- `cutaway` / `insert`：必须引用 sceneTargetId，可承载已有对白的画外声音；
  不复制对白、不虚构目标，画面是否切走由明确叙事意图决定。
- `environment_hold`：没有对白，必须指定插入节点前/后、时长和承载方式。

场景目标要包含：目标 ID、语义来源、世界/沙盘变换、bounds、焦点位置、可见性状态。
有效性校验按目标类别分流，环境镜头不检查“人物眼高”，但仍检查目标入画、
画幅安全、相机可达性和可执行时间。

先实测 UE 对话节点中的等待、镜头序列、隐藏节点与 NextID 规则，再选：
复用已存在的无对白时间节点，或新增专用镜头轨道/节点。
在没有确认引擎承载契约前，独立空镜仅作为设计建议，不写入 UE。
新增节点还需完整支持导出预检、用户确认、ID 分配、回读和失败恢复。

不能规定“每 N 镜插空镜”。应由建立地点、画外声音引导、道具信息、
延迟揭示、情绪释放等具体节拍触发；没有可靠环境目标时保持反应或长镜头。

## 推荐落地阶段

1. 只读场景定位与附近组件清单：用户确认落点，输出可复现的 sceneContext。
2. 轻量代理与 UE 可见性查询：本地比较机位，引擎确认粗筛的遮挡疑点。
3. 候选机位 RGB 图：支持人工对照，再增加视觉 provider 的实际图片输入。
4. 按需线性深度/对象 ID：处理无碰撞装饰、复杂遮挡与运动路径。
5. 可寻址场景目标与空镜时间线：完成 UE 时间承载实测后才开放独立空镜导出。

验收样例至少包括：同 BP 不同地图、同地图多实例、带旋转落点、阶梯高差、
窄门框、植被实例、无碰撞装饰、未加载子关卡、角色坐姿，以及长焦远景背景。
记录角色关键点在沙盘和 UE 同机位画面中的 NDC 偏差、遮挡一致性和导出回读结果，
而不是只统计红色预警数量。
