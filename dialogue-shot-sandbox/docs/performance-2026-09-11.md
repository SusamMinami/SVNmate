# 候选帧与协作状态读取优化

## 范围

本轮修改 `candidateFrameRenderer.ts`、`storyboardTaskStore.ts` 和
`traeBridge.ts`，不改变 UI、镜头规则、候选数量、全量评分协议、UE 轮询频率或
写入流程。实现已纳入 `v0.24.6`；验证过程没有改动 UE 资产。

## 实现

### 候选图资源按任务复用

- 原实现每帧创建 WebGLRenderer、Scene、角色代理、光源和输出 Canvas。
- 新实现一次 `renderRuleCandidateFrames` 调用只创建一组资源；逐帧更新相机、
  角色可见性和面向方向，JPEG 字符串仍逐帧独立编码。
- 保留 512×288、抗锯齿、sRGB、JPEG quality=0.78，以及全部原有代理几何与光照。
- 正常完成、初始化异常、单帧失败、整镜无可用帧均进入清理；网格线几何与材质也
  被释放，共享材质只 dispose 一次。
- 空候选不分配 GPU 资源，无浏览器环境仍返回 null。
- 本轮没有实现边生成边评分，也没有消除整段 JPEG 在请求期间的驻留。

### 协作状态合并读取

- `readStoryboardTaskSnapshot()` 从一轮任务目录读取生成队列和各状态计数；
  `/api/trae/status` 不再分别请求列表和统计。
- 正常情况下全目录扫描从四轮变为一轮，每个 JSON 读取、解析一次。
- 初次观察已过期的处理任务仍在文件锁内重新读取；只有仍过期才取消。
  新续期、已完成或已删除的任务采用锁内最新结果。
- 保留队列顺序、取消与心跳语义、磁盘为准的跨进程可见性和损坏文件报错。
- 这不是跨全部文件的原子事务快照；其他进程随后发生的更新在下次请求可见。
- 不建立常驻正文缓存或持久摘要索引。任务创建、查重等其他历史读取未改。

## 验证

新增 13 项单元测试：7 项渲染资源所有权，6 项任务快照；
已有队列和 MCP 集成一起定向执行，共 34 项通过。
首次全量 `vitest run src server` 执行通过 445 项；收尾时当前工作区已有
动画语音模块的其他并行修改，重新验证共 464 项全部通过；`npm run build` 通过，
保留现有主 bundle 超过 500 kB 的提醒。

新增桌面 Playwright 测试使用同一实现的两种生命周期进行对比：
12 张候选共用资源，对照每张使用全新上下文；JPEG 数据逐张完全相等，
画面 512×288，抽样识别到 1752 种颜色，截图人工检查非空。
这验证批处理没有携带前一帧状态，不是旧提交与新提交的逐像素对比。

单次本机独立执行：共用上下文约 148 ms，全新上下文约 177 ms。
全套并行回归执行时为 229 ms 与 369 ms。这里只记录观察值，
不把受机器负载和热缓存影响的单次耗时作为稳定性能承诺。
确定性的收益是上下文创建数从每帧一次变成每任务一次，以及正常状态读取
从四轮变成一轮。尚未测量 Electron 总工作集或真实大任务的内存降幅。

桌面全套共 48 项，候选图、VLM 全量评分、队列、小窗同步等全部通过。规则占位
动作测试不再依赖异步加载过程中的瞬时状态文案，改为验证既有动作实际可见且没有
可编辑下拉框；定向重跑与完整回归均通过。

测试辅助 Skill 的准备脚本在 Windows Git Bash 报不支持 cygwin，
报告 flush 也因未安装 utree 失败。实际测试使用项目本地 Vitest/Playwright，
未更换依赖或搭建外部测试工程。测试夹具开发中的错误导入和字段引用已经修正。
